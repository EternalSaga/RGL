# 项目黑话对照表

> **为什么会有这张表**：本项目文档为了省 token 造了一套简写（见下）。省的是文档的钱，
> 付钱的是**每一次对话**——模型每次开工都读 AGENTS.md + skills，会照着那个文体回话，
> 于是用户得自己解码。本表的用途 = 让"翻译成白话"这件事只有一个真相源。
>
> **本表只管"怎么说"，不改文档写作预算**：AGENTS.md 该压缩仍然压缩（skill
> `rgl-doc-placement` 的预算制继续有效）。要改的只有一件事——**对用户回话时用白话**。
>
> **本表就是术语名单的唯一真相源**（第一列 = 术语，` / ` 分隔同义写法；第三列 = 处置）。
> `tools/checks/config.py` 里**不抄这份名单**——抄了就得再写一条规则去对账两份副本。`just checks`
> 只查三件事：本表读得到吗、处置写的是词表里的值吗、登记的词还有人用吗
> （规则 → `docs/风格检查规则.md` §16）。

## 处置是什么意思

- **保留** = 这个词压缩的是真区别，白话写要一整句，继续用；但**第一次对用户提及时补一句白话**。
- **换掉** = 纯隐喻、没有代码或命令锚点，删掉不丢任何信息。对话里别说，文档里也别新增
  （`just checks` 棘轮：某个文件里这类词的条数只准降不准升）。
- **⚠ 两义** = 同一个词在项目里指两件不同的事，比黑话更累人。用之前先点明是哪一件。

## 对照表

| 术语 | 白话 | 处置 |
|---|---|---|
| 判据 | 一个检查用来判定"通过 / 不通过"的具体规则 | 保留 |
| 护栏 | 会点名的工具或构建检查，让错误做法直接过不去 | 保留 |
| 闸门 / 门禁 | 跑不过就中断构建或 push 的那道检查 | 保留 |
| 门 | ⚠ 两义：① 一个配置开关（如 `diagnostics.rpc`）② 一道会卡住构建的检查。用之前点明是哪个 | 两义 |
| 发射权 | 谁真正有权插入 barrier、决定资源布局（而不是只申报"我要什么"） | 保留 |
| 阳性锚点 | 一条**故意做坏就必须变红**的测试用例；它证明那个检查真的在起作用 | 保留 |
| 假绿 | 检查显示通过，其实什么都没验（空集合、恒真条件） | 保留 |
| 出声 | 工具在**没能真正检查**的情况下必须报错，而不是安静地返回"0 条问题" | 保留 |
| 漂 / 漂了 | 一份副本和它的真相源不再一致，且没有任何东西会喊 | 保留 |
| 冒烟 | 不开窗口、不要求 GPU，只验证"能跑起来、不崩"的那一遍 | 保留 |
| 台账 | `docs/还债总账.md`，全项目待办问题的唯一清单 | 保留 |
| 债- | 上面那份清单里一条编号的前缀，完整形态如 `债-129` | 保留 |
| 红线 | 硬性禁止，没有例外通道 | 换掉 |
| 射程 | 某个检查**看得到什么、看不到什么**（"不在射程内" → "这个检查扫不到它"） | 换掉 |
| 靶 / 造靶 | 测试或探针喂进去的那份输入，通常是专门合成的场景（`tools/qa_scenes.py`） | 换掉 |
| 裸奔 | 这条约定没有任何检查守着，只靠人记得 | 换掉 |
| 落点 / 归宿 / 载体 | 这条知识写在哪个文件里 | 换掉 |
| 收敛 | 把重复实现的多条路径合并成一条 | 保留 |

## 翻译示例（真实句子，改前 → 改后）

**改前**（AGENTS.md §项目哲学 3）：
> **申报 ≠ 发射权**（plan-only 红线）：申报面只拿"计划 + 校验"，barrier 与真实布局仍由模块给。
> 否则 `layoutDrift` 那类对账**变成恒真**。

**改后**：
> 模块可以告诉渲染图"我需要什么"，但渲染图不会替它插 barrier、不会替它决定内存布局——
> 这两件事仍然由模块自己做。**为什么不让渲染图代做**：项目里有个检查叫 `layoutDrift`，
> 专门查"模块是不是漏插了 barrier"。如果 barrier 改成渲染图插的，这个检查就永远查不出问题，
> 因为它自己就是那个该被它检查的人。

---

**改前**：`qa/configs/**` 冻结靶 0 处；`velocityField` 不在 lint 射程。

**改后**：`qa/configs/**` 里没有任何一份被冻结的测试输入；`velocityField` 这个配置键不在那个
检查的扫描范围里，所以改它不会有任何工具出声。

## 对话侧的三条（配合全局 `~/.config/opencode/AGENTS.md`）

1. 回复用完整句子 + 日常中文；内部简写第一次出现写成"白话说明（文档里叫 X）"。
2. 不用隐喻代替解释——解释"为什么"，不要把"为什么"压成一个箭头。
3. 指代文件 / 命令 / 债编号时顺手给一句它是什么。文档本体照旧可以很密，**这条只管对用户说话**。
