# 文档归宿裁决（AGENTS.md 是预算制，不是垃圾桶）

> 立规依据：12.3d 实操（AGENTS 376→249、调试历史 1806→985）。
> 核心命题：**文档只记录不阻止**。防线 = 测试 + 工具护栏；AGENTS.md 每多一行，
> 每次开工的注意力预算就多花一行，所以新增指令必须过下面的裁决树。

## 裁决树（新知识点进来先走这五问）

1. **是"以后永不违反 X"型不变量吗**（字节布局 / 数学契约 / 落槽规则 / 解析回落）
   → 做成**测试**（`tests/`，无设备毫秒级；设备级走 `TEST_SUITE("gpu")`）。
   红线：不写测试的不变量文档 = 两个月后重踩的坑（Frisvad 案例：两天 GPU 排查
   vs 4 行单测）。测试交付必须带变异红线声明 → skill `rgl-test-discipline`。
2. **是"能机制化为工具行为"的过程教训吗**（构建跳过 / 陈旧产物 / 判据缺失）
   → 做成**护栏**（`tools/checks/` 规则、`cmake/` 构建期检查、imgqa 判据、CLI 强制），
   护栏失效必须出声（"零警告"会被读成"干净"——参照 rules_layers.py 的失效也报 error 形态）。
   先例：stale SPV 双护栏（check_shader_deps.py + imgqa checkShadersFresh）。
3. **是某类操作才需要的操作性知识吗**（改 shader / 建模块 / 跑验证 / 写单测）
   → 进**既有 skill**（触发词命中哪个进哪个）；四个都不沾边且体量 ≥10 行才提议新 skill。
   现有分工：`rgl-verify`（运行/截图/测量）· `rgl-shader-contract`（反射管线）·
   `rgl-new-module`（模块基建）· `rgl-test-discipline`（测试纪律）· 本 skill（文档归宿）。
4. **是每次开工都需要的路由 / 红线 / 决策结论吗**（构建命令表 / 四库分层判据 /
   命名空间 / 用户拍板过的纪律）→ 才进 **AGENTS.md**，且写"结论 + 指针"不写论证。
5. **都不是**（机制详解 / 历史叙事 / 批次账）→ docs/ 对应文件：
   `技术概念.md`（机制深版）· `调试历史.md`（**只留难测的教训**：误诊叙事、负知识、
   症状指纹；已机制化事实删除，原文 git history 即档案）· `phase*_plan.md`（批次账）·
   `archive/`（已结题）。

## 修改 AGENTS.md 的三条操作纪律

- **先补目的地再删源**：任何 MOVE 先把内容完整写进 skill/docs 并核实承载，
  再删 AGENTS 段，最后修全仓指针——顺序错会制造信息真空期。
- **入册前实测**：文档会撒谎，代码不会。新增/保留的每条"现状描述"须 grep/读
  源码核实（实例：AGENTS 曾载"MASK alphaTest 未实现"而 alphaDiscard 已落地 ×5、
  "state_kit 四段"→"九段"而实为**十段**（2026-10-02 实测；名单类口径的根治办法是别抄——
  现收归 `pass_vocabulary` 单一真相源 + static_assert）、"0/30" 数字口径漂移）。发现文档与代码矛盾时，
  **裁决方向 = 代码就范于声明还是声明就范于代码**，显式记录（实例：issue_history
  双条件门声称 vs 代码单 bit → 落地双门收口）。
- **删减判据**：删段落前问"三个月后的人还会不会因缺这段重犯"。会 = 留（哪怕 AGENTS
  偏长）；不会（信息已由测试注释/护栏/skill 承载）= 删，留一行指针 + 沉淀地址。
  行号引用一律改条目名（行号必然漂移）。

## 反模式（本项目踩过的）

- 把裁决树的 1/2/3 答案写进 AGENTS"已知问题"节 → 三机三个月后它变成谎言行。
- "已知问题"节混装"现行契约" → 节头口径与内容自相矛盾（收口方式：节头明说
  "只列未解决问题与标『现行』的契约"）。
- 同一教训在 AGENTS 两处逐字重复、或 AGENTS 与 docs 深版全文重复 → 只留一份 + 指针。
- 给写不出断言的东西硬凑测试（硬件观察、决策记录）→ 那是 DOC 归宿，别假装机制化。
