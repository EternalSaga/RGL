# 文档归宿裁决（AGENTS.md 是预算制，不是垃圾桶）

> 核心命题：**文档只记录不阻止**。防线 = 测试 + 工具护栏；AGENTS.md 每多一行，每次开工的
> 注意力预算就多花一行，所以新增指令必须过下面的裁决树。

## 裁决树（新知识点进来先走这五问）

1. **是"以后永不违反 X"型不变量吗**（字节布局 / 数学契约 / 落槽规则 / 解析回落）→ 做成**测试**
   （`tests/`，无设备毫秒级；设备级走 `TEST_SUITE("gpu")`）。不写测试的不变量文档 = 两个月后
   重踩的坑。测试交付必须带变异红线声明 → skill `rgl-test-discipline`。
2. **是"能机制化为工具行为"的过程教训吗**（构建跳过 / 陈旧产物 / 判据缺失）→ 做成**护栏**
   （`tools/checks/` 规则、`cmake/` 构建期检查、imgqa 判据、CLI 强制），**护栏失效必须出声**
   （"零警告"会被读成"干净"）。
3. **是某类操作才需要的操作性知识吗**（改 shader / 建模块 / 跑验证 / 写单测）→ 进**既有 skill**
   （触发词命中哪个进哪个）；四个都不沾边且体量 ≥10 行才提议新 skill。
4. **是每次开工都需要的路由 / 红线 / 决策结论吗**（构建命令表 / 分层判据 / 命名空间 / 用户拍板过的
   纪律）→ 才进 **AGENTS.md**，且写"结论 + 指针"**不写论证**。
5. **都不是**（机制详解 / 历史叙事 / 批次账 / **教训**）→ docs/：`技术概念.md`（机制深版）·
   **当前任务文档**（`phase*_plan.md` 里正在做的那篇）= 教训的唯一落点 · `archive/`（已结题）。
   **不再有全局调试历史**（2026-10-08 删除，写法见下节）。

## 教训怎么写（2026-10-08 换轨；旧「只增不改」已废）

- **就近**：教训写进**当前任务文档**对应批次那一节，不新建全局时间线文档，也不为几条教训开新文件。
- **可改写，且推翻即删**：被实测推翻的旧教训**直接从正文删掉**，只留正确做法。发现文档与实测矛盾
  → 以新发现为准**就地改写**，不留"旧结论 + 更正注记"双层。错误版本靠 git 沉淀（`git log -- <文件>`），
  它不该留在正文里误导下一个会话——**"只增不改"的真正代价就是把错的东西当权威读**。
- **能测的必须测**：先回裁决树 1/2（TEST / GUARD），只有写不出断言的（硬件观察、决策记录、负知识）
  才准留 DOC。
- **负知识必须带失效条件**——"X 走不通 / 别做 Y"是**最不稳**的一类断言：证成范围天然比表述窄、
  否的常是当时的实现而非这件事、前提随引擎漂、且写不出阳性锚点（⟹ 被推翻时没人会知道）。写法 =
  抄 imgqa 反模式登记的三件套：**作用域**（哪个算子 / 激励 / 论域 / 基线下不成立）+ **仍然要做的
  部分**（别据此冻结什么）+ **什么实验会推翻它**。真发生过：否的是"L1 总量"这个**算子**，被读成
  "移动机位不值得测"，一个激励白冻两天。**禁令与带失效条件的假设，差的不是格式，是三个月后会不会
  被读宽**（机器可读那半见 skill `rgl-test-discipline` §负知识的作用域）。
- **历史指针**：引用已删文档里的旧条目写 `git:调试历史 <日期>`（`git:` 前缀 = 原文只在 git 历史里，
  不在工作树）。已机制化：`doc_pointer_checks`（§1.7）对**悬空文档指针**与**退役文档名复发**点名。

## 四条操作纪律

- **发现即删，不许"记一笔以后收"**（2026-10-14 定）：读 AGENTS/docs 时撞见过期条目——状态与文档头部
  矛盾、指针悬空、批次已结案——**当场删掉，随当前改动一起提交**。这类条目的代价不是"多一行"，而是
  下一个会话**平铺直叙地把它当权威读**；而"以后收"不会发生（实测：AGENTS 索引里 3 条已漂状态挂了数周，
  同批还抓到 2 条早已悬空的入站指针，全程没有任何东西喊过）。两种形态分开处置：
  - **条目过期、文档还现行** → 删掉条目里的状态/摘要（只留「什么时候该读它」与「读哪一节省钱」），
    或整条删掉。护栏 = `agents_index_status_checks`（§1.9）点名日期 / 批次号 / 状态词。
  - **文档本身结题** → 整篇搬 `docs/archive/` 并同步其 README；**不是**只删 AGENTS 那一行——文件还在
    磁盘上就会被 §1.6 报「未入索引」，那条警告正是在替你确认"你删错了对象"。
  删前照走下面两条：实测裁决方向（以代码 / 文档头部为准，不以记忆为准）+ 三层筛核实承载。
- **先补目的地再删源**：任何 MOVE 先把内容完整写进 skill/docs 并**核实承载**（逐条比对目标文件
  是否真的收了），再删源段，最后修全仓指针——顺序错会制造信息真空期。
  ⚠ 核实要落到"哪几行"：曾以为深版表已覆盖 AGENTS 简表，实测**7 个模块在两份 docs 里都没有承载**，
  直接删就是丢信息。
- **入册前实测**：文档会撒谎，代码不会。每条"现状描述"须 grep/读源码核实。发现文档与代码矛盾时，
  **显式裁决方向** = 代码就范于声明，还是声明就范于代码。
- **删减判据（三层筛，2026-10-07 定）**：逐段问三句，**任一为「是」即删**（留一行指针 + 沉淀地址）：
  1. **编译器 / source_checks / 构建闸门会点名吗？** 会 → 删。文档不重复编译器已经会说的话。
     （实测：`redefinition of default argument`、`-Wreorder`、`vk::raii` 默认构造已删除、
     FILE_SET 漏登记的 `FATAL_ERROR`、扩展名白名单、Doxygen 块——全都不用写。）
  2. **读一个文件就知道吗？** 是 → 删（产物路径、依赖清单、configs 字段、模块清单）。
  3. **三个月后的人还会因缺这段重犯吗？** 不会 → 删。
  反过来，**只有"看不见的原因、顺序、陷阱"值得占预算**：静默错（`glm::radians()` 因
  `GLM_FORCE_RADIANS` 退化成恒等函数）、UB（CreateInfo 悬空指针）、假绿（空集合断言）、
  破坏性操作（变异回滚用 `git checkout` 会冲掉未提交实现体）。
  ⚠ **删前必须实测"兜底者究竟是谁"**：本轮先误以为两条 partition 坑"编译器会报错"（实测 clang
  对其中一条 rc=0 静默通过），再查到它们其实由项目自己的 source_checks §1.1/§1.2 点名——
  **结论仍是删，但理由完全不同**。别拿猜测当判据。

## 反模式（本项目踩过的）

- **抄名单**（最隐蔽的一类，因为抄的时候完全正确）：工具规则清单、模块清单、反模式名单、
  判据条数、债编号上界、`file.cpp:437-489` 行号指针。**副本必然漂**，而且漂了之后会被读成权威。
  正确形态 = 指向真相源（`config.py` / `CMakeLists.txt` / `imgqa refuse` / 条目名）。
  2026-10-07 一次瘦身里同批抓到 4 处：skill 抄了 checks 规则清单、AGENTS 抄了模块清单、
  台账手抄了 6/8 条反模式名、台账写死"债-00…债-29"（实际已到 64）。
- **AGENTS.md 指向不存在的文档路径** → error（`agents_doc_index_checks` 保留的**单向反查**）。
  🔴 **「新建 `docs/*.md` 须在 AGENTS 挂号」这条已于 2026-10-15 随正查一起退役**（owner 拍板「索引在我
  脑子里」，判据真相源 = `tools/checks/rules_text.py` 的 `agents_doc_index_checks` docstring）
  ⟹ 新建文档**不需要**挂号，`ls docs/` 是真相源；AGENTS「其他文档」只挂 owner 主动挂号的少数
  **条件路由**条目，判据是"每次开工都可能需要"，不是"这篇文档有用"。
- **AGENTS 索引条目写文档状态**（日期 / 批次号 /"已落地·挂起·冻结"）：文档头部已有状态行，索引再写
  一遍 = 同一状态两份载体，而推进文档的人不会记得同步 AGENTS ⟹ **漏一次永久错**。2026-10-14 实测
  抓到 3 条已漂，且都漂在会误导的方向（把文档明写的"非反转"记成"已反转"、把已恢复推进的轴记成
  "挂起"）。索引只写两件事：**什么时候该读它** + **读哪一节省钱**。已机制化：
  `agents_index_status_checks`（§1.9；节被改名走 error 而不是静默 0 条）。
- **全局「只增不改」调试时间线文档**（原 `调试历史`，2026-10-08 删除）：只增不改 ⟹ 被推翻的结论
  永久留在正文，而下一个会话读它是**平铺直叙地读**，不会先怀疑自己读到的是过期版本。教训要按
  "当前任务文档 + 推翻即删"写。删文档的复发形态是从 git 捞回来重建 ⟹ 已机制化：
  `doc_pointer_checks`（§1.7）把退役文档名写进 `config.RETIRED_DOC_NAMES`，再出现即 error。
- **在 AGENTS 维护"已知问题 / 现行边界"清单**（原「已知问题」节，2026-10-14 整节删除）：它是代码
  注释与任务文档的**有损副本**，且**会静默变错**——删前实测 8 条里已有一条被批 13.6/14.5 推翻
  （AO 施加点早就不在 tonemap 合成处），另有两条入站指针早已悬空（`texture_upload` 指的"Phase 5.5
  近似清单"、`VmaBuffer` 指的「渲染图边界」）。正确形态 = 断言住**使用点**（shader / 模块头注释）、
  契约住**测试**、未解决项住 `docs/还债总账.md`、读数住 `docs/cpu_perf_plan.md`。
- 同一教训在 AGENTS 两处逐字重复、或 AGENTS 与 docs 深版全文重复 → 只留一份 + 指针。
  自己写出"XX 文件已一字不差承载"这种话 = 已经承认这是第三副本，删。
- 给写不出断言的东西硬凑测试（硬件观察、决策记录）→ 那是 DOC 归宿，别假装机制化。
