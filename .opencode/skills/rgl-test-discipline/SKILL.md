# 写测试的硬纪律

## 断言有效性

- **阳性锚点**：每条断言先问"如果这段代码从未生效，这条断言会绿吗"。会绿 = 无效断言，必须重写。
- **反向用例**：guard / 早退分支必须配一条"不该触发"的用例，否则无法区分"没触发"与"坏掉了"。
- **辅助函数也要有独立判据**，且判据的数值噪声必须**远小于**它要检测的信号。
  测试代码的 bug 和被测代码的 bug **症状一模一样**——曾有 helper 把 `inverse(view*proj)` 写成
  `inverse(proj*view)`，在 `view = identity` 下**恰好正确**（两种顺序此时相同），换真机位才炸；
  而该 helper 的世界空间版在 near/far 比极大时 float32 反投影误差就淹没了信号（判据遂改到视空间做）。
- **断言要照源码写，不照记忆写**：一轮测试里写出过 10 处「我以为的行为」，**全部是错的**
  （段名、枚举拼写、fallback 语义、"有没有某个守卫"都会记错）。**先读实现再写期望**，否则写出来的
  是「测试在教引擎怎么改」而不是「测试在验引擎做了什么」。
- **断言独立于实现**：期望值来源 = 数学契约 / 闭式解 / 实机实测，不来自记忆也**不抄被测码**。
  与上一条不矛盾：照源码写是"先弄清引擎做了什么"，独立于实现是"期望值的**出处**必须是被测码之外的第二判据"。

## 确定性

- 随机性只用 `tests/test_support.cppm` 的 `Lcg` + 写死种子，禁 `rand()`/`random_device`
  （真随机的失败无法重跑，"上次跑过"≠"这次验的是同一组输入"）。

## 变异与验收

- **验证靠变异测试**：改坏被测数据逐个确认测试变红——**"测试通过"不等于"测试有效"**。
- **每条测试带「变异红线」声明**：文件注释里写清"哪个变异让我红"；答不出 = 摆设，不配进门。
  范例 = `tests/test_frisvad_tangent.cppm`。worker 交付的测试由主 agent **当场变异验红后才入账**，
  且质检变异形态与 worker 所验不同。
- **变异回滚只准文件备份 `cp`，禁用 `git checkout -- <file>`**：本批未 commit 的实现体会被一起
  冲掉（踩过：后续变异全变 MUTATE-FAILED，白跑一轮）。要么先 commit 再 checkout，要么
  `cp f f.bak` → 跑 → `cp f.bak f`。
  **⚠ 同一条防线的三个「陈旧二进制」变体（2026-10-10 实测各踩一次，全都表现为假绿/假红）**：
  ① 备份**别保留 mtime**——`cp -p` / Python `shutil.copy2` 会让回滚后的源文件比构建产物还"旧"，
  ninja 判定无需重编，症状是"回滚了测试仍红"（真相是二进制还是变异那份）；用不带 `-p` 的 `cp`，
  或回滚后 `touch` 一下。
  ② 变异脚本**必须显式建测试目标**——`tests/` 是 `EXCLUDE_FROM_ALL`，`just build` **根本不编**
  `rgl_tests`，拿它跑变异 = 全程旧二进制 = 变异"全绿"。要 `cmake --build build --target rgl_tests`。
  ③ 变异脚本**必须核对构建自身的返回码**——`cmake ... | grep error; echo $?` 拿到的是 **grep 的**
  退出码（恒 0），构建失败会被读成"编译通过 + 测试全绿"（2026-10-10 实测踩过，一条本该红的变异
  被读成绿，差点当成"测试无效"的结论入账）。要么不管道直接取返回码，要么用 `PIPESTATUS`。
  ④ **每条变异还原后必须重跑基线并断言全绿**——①②③ 都是"防"，这条是"测"：未预料到的陈旧产物
  或还原残留，会在还原后的基线重跑里当场现形，而不是把后面一整轮变异读数静默污染。
  （2026-10-12 实测：harness 用 `shutil.copy2` 还原 → 保留旧 mtime → ninja 判定无需重编，
  明明违反了①却没人出声，直到某条变异"该红不红"才追回来。）
- **谓词类变异要保留参数使用**：`return false` 直接 `-Werror=unused-parameter` 编译红，拿到的是
  「编译失败」而非「测试判据红」——写 `x && false` / `x || true` 才测得到判据本身。
- **对空集合的断言要加前提守卫**：`for (x : all) 断言(x)` 在 `all` 为空时恒真 = 假绿。先钉
  `!all.empty()`（或断言总数）再遍历。
- **教训条目带「沉淀地址」**：收账时裁决三选一——`TEST: <路径>`（断言已存在/新增）/
  `GUARD: <机制>`（工具护栏，做不掉就先记债）/ `DOC: <理由>`（硬件观察/决策记录/负知识——
  断言写不出来的才准留纯文档）。文档只记录不阻止，防线是测试和护栏。
  **DOC 的落点 = 当前任务文档**（全局调试历史已删，2026-10-08）；被实测推翻的旧教训**直接删**，
  不留"旧结论 + 更正注记"双层 → skill `rgl-doc-placement` §教训怎么写。

## 负知识的作用域（登记反模式 / 作废结论）

- **作用域已机制化，别在文档里重述**：imgqa 反模式登记现在是
  `AntiPatternInfo{name, scope, why, stillOpen}`——`scope`（算子/激励/论域/基线）排第 2 位
  **无默认值 ⟹ 漏填是编译错误**；`stillOpen`（**未被否、仍然要做**的部分）由 `imgqa selftest`
  强制非空且必须含反引号包裹的具体命令名。**读反模式必须连 `stillOpen` 一起读**：作用域读宽一格
  就连带冻掉后来真正需要的激励（真发生过：否的是"L1 总量"这个**算子**，被读成"移动机位不值得测"，
  那个激励白冻两天，而后来唯一抓到根因的判据用的正是它）。
- **作废一条结论必须挂重测债编号**，不许只写"已作废"。作废本身往往是对的（读数跑在坏构建上），
  真正的债是修好后没人回去重跑。

## 运行与工具

- 单测结果以 `just test` 为准（它先构建再跑）；**直接跑 `build/tests/rgl_tests` 可能拿到陈旧二进制**。
- 设备级用例写进 `TEST_SUITE("gpu") { … }`（本构建不用 tag 形态），在无设备机器上**必须 FAIL
  不 SKIP**——静默跳过 = 假绿。
- **判据工具自己要有自检**：闭式解探针的 PNG 读图器配了编解码**往返自检**（各 filter 编码 → 读回 →
  逐像素比对）。不测这段，编码器一旦写出非 0 filter，读图器会静默读错像素，而"闭式解不符"会被一路
  归因到着色链上——那是最贵的一种假线索。

## modules 环境坑

- **modules 下 `std::initializer_list` 不从 `import` 带进来**：要用 `for (x : {a, b})` 或
  `extent = {w,h,1}`，本 TU 的 GMF 里**必须有一个真 STL 头**（如 `#include <initializer_list>`），
  只 include doctest 不够。症状很有欺骗性：花括号推不出类型后退化成 void，报
  「ambiguous with void」或「initializer_list was not found」，离真因两跳。
  同目录用 `<cmath>` 的测试文件是**巧合受益者**，不是范例。
