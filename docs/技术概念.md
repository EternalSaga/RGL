# 技术概念与设计决策

> **状态**：现行（核心 Vulkan 模式与设计决策的权威记录；代码演进后在此更新）

## 核心 Vulkan 模式

### Synchronization2
所有屏障均使用 `pipelineBarrier2` + `vk::DependencyInfo`，不再使用旧的 `pipelineBarrier` API。

### Dynamic Rendering（动态渲染）
不使用 Render Pass，通过 `beginRendering` + `RenderingInfo` 直接开始/结束渲染。无需创建 RenderPass 对象，简化了渲染流程。

### ShaderObject（着色器对象）
不再创建 Pipeline，直接通过 `bindShadersEXT` + dynamic state 绑定着色器。省去了 PipelineLayout 和传统 Pipeline 创建流程。

### Push Data
通过 `vkCmdPushDataEXT` 推送 `DrawArgs` 数据到着色器。与 descriptor heap 独立，在 shader 中通过 `[[vk::push_constant]]` 访问。push data 区域大小 ≥256 字节。

### DescriptorHeap
`VmaDescriptorHeap` 管理单个 GPU-visible buffer。Descriptors 通过 `vkWriteResourceDescriptorsEXT` 写入 heap slots（slot 由 `Resources::allocSlot(SlotSegment, name)` 按用途段分配：`geometry` 段（内建几何 + 模型拼接块）、`texture` 段（首槽 = 白纹理契约）、`runtime` 段（scene data / RT 采样槽 / mip-gen / env-prefilter / cull）。几何段连续性断言仍见 `AssetTable::expectedGeometrySlot`；白纹理契约只断言等于纹理段首槽，不再依赖跨段上传顺序。`vkCmdBindResourceHeapEXT` 在渲染前绑定 heap。

### 渲染图（RenderGraph，Phase 6）
帧拓扑从"drawFrame 硬编码三段 + 手写 barrier"升级为**声明 → 编译 → 执行**三层：

1. **声明**（`configs/render_graph.lua`，sol2 沙箱，缺文件回落默认三段图）：
   `attachments`（kind=swapchain/depth/offscreen）+ `passes`（outputs/inputs 带 usage、
   load/store/clear、state/drawSource 名字字符串）。纯数据，零 Vulkan handle 零每帧回调。
2. **编译**（`render_graph::compileRenderGraph`，启动期 fail-fast）：结构校验
   （读先于写/同 pass 读写冲突/DontCare 后仍被使用/usage 与 kind 匹配/blit 拓扑/
   swapchain 必须被写）+ **barrier 自动推导**——每个 attachment 一条"上次 usage"游标，
   跨 pass 转换按查表物化：

   | usage | layout | stage | access |
   |---|---|---|---|
   | colorWrite | ColorAttachmentOptimal | ColorAttachmentOutput | ColorAttachmentWrite |
   | depthWrite | DepthStencilAttachmentOptimal | EarlyFragmentTests | DepthRead\|DepthWrite |
   | sampleRead | ShaderReadOnlyOptimal | AllGraphics | ShaderRead |
   | transferRead | TransferSrcOptimal | Transfer | TransferRead |
   | transferWrite | TransferDstOptimal | Transfer | TransferWrite |

   **帧首规则**：swapchain/depth = oldLayout `eUndefined` + src TopOfPipe/eNone（内容按
   loadOp 重建，与图化前实践逐位一致）；offscreen 持久图 = 执行器跨帧追踪的真实布局
   （帧间已由 fence 同步，src 仍 TopOfPipe）。**跨 render pass 实例 LOAD 的执行依赖** =
   同布局也发 identity barrier（写→写；读→读跳过——写后的首条 read barrier 传递覆盖
   后续所有读者）。帧末 present 转换 src 由 swapchain 最后 usage 派生，submit
   waitStage = 命令流首个 swapchain barrier 的 dstStage（直渲图 ColorAttachmentOutput、
   blit 上屏图 Transfer——旧手工特判被机制接管）。
3. **执行**（`Renderer::drawFrame` 盲循环）：逐 pass `emitBarriers`（物化 +
   `attachmentLayouts` 追踪推进）→ `beginRendering`（逐 pass 附件）→
   `applyDynamicState(pass.state)` → 段内逐 draw（`pass.drawSource`→FrameDrawList
   段边界）→ `endRendering`；blit pass = transferRead→transferWrite 整幅拷贝。
   **图的边界**：heap host-write barrier、scene staging copy、heap 绑定、acquire/present
   信号量与双 fence 帧槽 = 数据通路/时序基础设施，不入图。

设计定位：Frostbite 第一代全自动图只保留核心一条（自动 barrier），aliasing/pass
fusion/多线程录制不做——与 GDC 2022 "The Future of Render Layers"（API-tight）收敛
方向一致。验收 = 图化后截图与旧硬编码路径 **BIT-IDENTICAL**（headless swapchain 回读
sha256 对账，基线 71e50427）；`renderGraphSelfCheck()`（无 GPU）main 启动期常跑。

## 着色器缓冲访问

### 三种载体的分工（2026-10-13 换轨：scene data 已全量类型化）

Descriptor heap 模式下 shader 侧缓冲访问的**现状**是三种载体并存，按"要不要每帧换绑 /
元素是否同构"选，不是按历史习惯：

| 数据类型 | 访问方式 | 原因 |
|---|---|---|
| 每绘制小数据（MVP、光源数等） | **Push Data** | ≤256B，零 descriptor 开销，最快 |
| **scene data 全部 12 个区** | **`ConstantBuffer<T>`（UBO）/ `StructuredBuffer<T>`（SSBO）**，binding 22–33 | 布局由反射契约给，shader 侧**一个字节数都不写**；`sceneData` 全区 `ByteAddressBuffer` 已退役（R6 永久禁止，见下） |
| 同构表（簇化产物、cull 私有表、IZB 链表、顶点/索引池） | **ByteAddressBuffer** | 仍是手写字节偏移——**这是遗留，不是设计**；逐条归属见 `docs/constantbuffer_迁移计划.md` §9.10 |

**scene data 为什么可以全量类型化**（三条机制，别再重新推一遍）：一个物理 buffer + **N 条
子范围描述符**（拆描述符不拆 buffer，VUID-…-12350/12351 允许 buffer 内非零偏移）⟹ 每帧 CPU
代价增量 = 0；mapping 按 **SPV 实际声明的 binding** 过滤 ⟹ 新增 binding 不需要在 C++ 侧登记
消费者；布局原地重排到 **256B 对齐** ⟹ 迁移期零数据复制。全过程与每批实测 →
`docs/constantbuffer_迁移计划.md` §9。

### StructuredBuffer 的 stride：旧结论已被实测推翻（2026-10-12）

**旧结论（错）**：「HLSL `StructuredBuffer<T>` 强制元素 stride ≥16 字节对齐，与 C++
`sizeof(T)` 不一致，导致静默数据损坏」——那是 **std430 口径**的行为，不是载体的固有属性。
项目全量带 `-fvk-use-scalar-layout`（`cmake/RglSlang.cmake` 的 `SLANG_FLAGS` 唯一声明点），
scalar layout 下 `ArrayStride` **就是** `sizeof(T)`：同一个 `struct { float3; float3; }`
（`sizeof` 24），带 scalar layout 编出 `ArrayStride 24`、不带编出 `32`。

**现行边界**：`StructuredBuffer<T>` 的 `T` **必须是反射契约类型**（`R3`，集合机械取自
`rgl/generated/*_types_generated.cppm`），且 `ArrayStride == sizeof` 由 **`R4`**
（`tools/check_spirv_stride.py`，每次 `just build` 现场编探针对账）+ 设备端往返
（`just test-gpu -tc="*stride*"`，stride 8 / 44）两道护栏守着。无契约的裸 struct 仍然红。
完整实测与理由 → `docs/constantbuffer_迁移计划.md` §8。

> 本节保留的理由：`ByteAddressBuffer` 在**同构表**上仍是现状形态（49 条裸偏移，逐条归属见
> 迁移计划 §9.10），但它现在是**选择/遗留**而不是**被迫**——把它当"因为 StructuredBuffer
> 会静默错位所以不能用"读，就把那条已被推翻的理由又续了一年。

### 为什么 scene data 用 UBO/SSBO、别处还留 ByteAddressBuffer

旧结论"UBO 的缓存优势可忽略、ByteAddressBuffer 已覆盖所有场景"**已被推翻**：真正的理由从来
不是性能，而是**类型化把布局从人肉双源变成反射契约**——`objectDraws[i].baseColor` 写错字段名是
编译错误，`sceneData.Load4(525312u + 16u)` 写错数字是**静默读错行**。scene data 已按这条换完。
剩下的同构表（簇化 / cull 私有 / IZB / 顶点池）留着字节偏移是**遗留债**：它们的元素类型还没进
反射契约，且各自的越界判据不在 scene data 那条线上（`R5` 棘轮只准减不准增，`R6` 已把
`sceneData` 全区读永久封死）。

## 设计决策

### GPU 评分：`pickPhysicalDevice`

评分权重：`coreCount * 1000 + vramGB * 10 + discrete(+500) / integrated(+200)`

流处理器数量是性能的决定性指标，其次是显存，最后是 GPU 类型。这避免了高端核显被误排到弱独显之后（例如高端 iGPU 搭配入门级亮机卡）。

### Present Mode：窗口 `eImmediate` / headless `eFifo`

直接返回 `eImmediate`，不可用则抛异常。

headless 模式（`VK_EXT_headless_surface`，present 为 no-op）无 eImmediate，走 `selectHeadlessPresentMode`：优先 `eFifo`，回落首个可用（vkswapchain.cppm）。

在 Wayland 下，compositor 已管理 triple-buffering 和帧同步。`eImmediate` 是正确选择，无需回退。

**双模式开关（批 9.3，2026-09-27）**：`configs/runtime.lua` 的 `present_mode = "immediate"|"fifo"`
（默认 immediate = 上述现状）。窗口路径 `vkswapchain::createPresentMode` 按偏好分支（fifo = find
eFifo，spec 必保；immediate = 原硬要求路径）；headless 忽略此键恒 eFifo。用途 = phase9 9.4 需
FIFO vs eImmediate 对比证据（决策记录见 `phase9_plan.md` §9 D5，修订 archive 2026-09-01
"不加开关"）。

**批 9.4 判定（本机 forward 1280×720 / RADV Strix Halo / 165 Hz）**：两模式的帧墙钟与 IPD
分布**在噪声内重合**（avg 7.10 ms vs 7.10 ms）且 `drop` 双零——因为本机是 CPU-bound
（CPU 录制 7.03 ms > GPU 2.98 ms），帧率被 CPU 压到 ≈141 fps **低于**刷新率，FIFO 的 vsync
背压根本没触发。故**当前不需要帧率上限/CPU pacing**；开关保留作为"负载形态变化后的复测入口"
（Phase 11 阴影若把成本推向 GPU 侧则需复测）。完整判定链 = `docs/phase9_plan.md` §10。

### Swapchain 图像数量：Wayland 不加 1

Wayland compositor（如 KWin）自身维护 triple-buffer。额外 +1 会变为 quadruple-buffer，增加不必要延迟。X11 仍 +1 以保持向后兼容。

### Viewport Y 轴翻转

`viewport(0, height, width, -height, 0, 1)` 反转 Y 轴。

Vulkan NDC 的 Y 轴向上，窗口/屏幕坐标向下。翻转后视图与预期坐标系一致。

### 双 Fence：inFlight + present

使用两套 fence（`inFlightFences` + `presentFences`），而非单 fence。

**问题：** 在 triple-buffer swapchain（KWin）下，单 fence 附加于 `queueSubmit` 无法追踪异步的 `presentKHR`。fence 信号时 present 可能仍在等待，导致 semaphore 重用违规（VUID-00067）。

**方案：** 利用 `VK_KHR_swapchain_maintenance1`：
- `inFlightFences` — 附加于 `queueSubmit`，追踪 command buffer 完成
- `presentFences` — 通过 `SwapchainPresentFenceInfoEXT` 附加于 `presentInfo.pNext`，追踪 present 完成

`drawFrame()` 开始时同时等待并重置两个 fence，确保 semaphore 和 command buffer 在 submit 和 present 均完成后才安全重用。

### PresentFenceInfoKHR

使用 `vk::SwapchainPresentFenceInfoEXT`（`SwapchainPresentFenceInfoKHR` 的 typedef 别名）于 `presentInfo.pNext`。

现代同步方式，利用 `VK_KHR_swapchain_maintenance1` 实现更干净的 present 端 fence 追踪。EXT 和 KHR 的 sType 值相同。

### DrawArgs 布局规则

所有 slangc 编译（反射 + SPV）统一 `-fvk-use-scalar-layout`（scalar 布局）：DrawArgs 全字段 4 对齐、零 padding，与 C++（glm 自然对齐）逐字段一致。**Phase 7b+ bindless 化后（2026-09-10，`4283b67`）DrawArgs 只剩 `objectIndex@0`（4B）**——原先的 mvp@0 / totalTriangles@64 / vertexOffset@68 / baseColor@72 / roughnessMetallic@88 / objectIndex@96（共 100B）已全部迁入 scene data per-object 表（`scene.slang` readObjectMvp / readObjectDraw），push 不再带它们。尺寸由 `material_types_generated` 的 `static_assert(sizeof(DrawArgs) == 4)` 钉死（漂移即编译错，消息 "Size of C++ struct DrawArgs does not match shader reflection!"；逐字段偏移则由 `material_schema.lua` 与 slangc 反射 JSON 比对）。运行时错配症状 = shader 从 push data 读到垃圾（静默画面错，非校验错误）。**历史尺寸口径**（旧文档/日志里出现的 100B / 36B 是当时的实测值：100B→NV 驱动约 112 条序列挂死、36B（去 mvp）→约 1200 条挂死、4B→1591 全量不崩，见 `material.slang` 头注释与 `git:调试历史` 2026-09-10 条目）。

### Matrix 布局

Slang 面向 Vulkan/SPIR-V 时 `float4x4` 默认为 column-major，与 `glm::mat4` 一致。`mul(M, v)` 严格计算 `M×v`（列向量）。**两端内存布局相同，直接透传，切勿 `glm::transpose()`**。

### 帧首丢弃规则 `oldLayout = eUndefined`（原 colorToDrawBarrier）

Swapchain image 第1帧 layout 为 `Undefined`（刚创建），帧2+ 为 `PresentSrcKHR`。`eUndefined` 作为 `oldLayout` 在 spec 中**唯一正确**——它覆盖两种状态，无需分支判断。

渲染图化后该规则由 `compileRenderGraph` 的 frameStartDiscard 固化（swapchain/depth 帧首 oldLayout = eUndefined + src TopOfPipe/eNone），执行器按 `plan.oldLayoutDiscard` 发射（vkrenderer emitBarriers）。

### Push Data 无需显式 mapping

`[[vk::push_constant]]` 在 descriptor heap 模式下不需要显式 mapping。Spec 3.4.1 明确说明 push constants 以旧方式访问，只是不再需要构建 pipeline layout。

## 构建检查工具机制（source_checks 深版）

> 自 AGENTS.md 下沉（2026-09-13 瘦身；2026-09-23 doc_check/style_check 合并为
> `tools/checks/` 单包单入口）。仅当修改 `tools/checks/` 本身时需要；规则红线（写代码要
> 遵守的）见 skill `rgl-new-module`；各模块的坑详见其源文件头注释。

- `source_checks`（ALL，2026-09-23 合并；**add_dependencies(rgl) 等编译完成后才跑**）：
  单入口 `tools/checks/main.py --build-dir build` 一次跑样式 + Doxygen 两套规则。
  **工具要求 Python ≥3.14**（2026-09-24 现代化拆分）。模块布局：
  `models.py`（Warning/阈值/TypedDict）· `fs.py`（pathlib 遍历）·
  `rules_metrics.py` / `rules_text.py` / `rules_doxygen.py`（三块判定）·
  `metrics.py`+`worker.py`+`cmdclean.py`+`clangbind.py`（解析与缓存）·
  `config.py`（名单阈值）。每个 .cppm **一次 libclang parse（ctypes 进程内），同一 TU 上再跑 Indexer API 采集
  全部声明（穿透 `export`）+ 回调内就地算函数体指标**——样式指标与 doc 声明表共享同一
  份 AST 与同一份缓存 `build/checks_cache/`（键 = CACHE_VERSION+源字节+命令 sha256，
  v6 起含 decls 表）：增量秒级（缓存命中全量 <2s），全量 77 单元 4 worker 分钟级。
  `--only style|doc` 只过滤规则求值不省解析；`just checks` / `doc-check` / `style-check`
  别名。竞态契约（坑 4c）：libclang 读 ninja 半写 BMI/.modmap 会 crash/NULL，主防线 =
  CMake 依赖串行化；worker 内 bmi_stable 双采样 + 1/2/4s 退避重试兜底手动并行场景；
  耗尽按"检查失败（跳过）"上报。非 `--strict` 恒 exit 0，任何失败不阻断构建。
- **为什么 Indexer 而非游标遍历/文本 dump（坑 7，2026-09-23 实测）**：`-std=gnu++23` +
  `-x c++-module` 下 `export` 声明在 libclang 游标树 = 0 子的 UnexposedDecl，
  `clang_visitChildren` 进不去（旧 stylecheck 对接口文件 export 类的方法/字段**整体
  盲区**）；去 `-std` 虽可见但 BMI 加载失败、类型解析成 error 型。Indexer 回调穿透
  export 且带 `isImplicit`（旧文本 -ast-dump 双管线随之废弃，行为对账 = git:调试历史
  2026-09-23 条目）。连带修正：FUNC_SPELLINGS 的 Constructor/Destructor/ConversionFunction
  拼写从匹配不上 LLVM 22（CXXConstructor/CXXDestructor/CXXConversion）→ ctor/dtor
  指标自 v6 起才真正入规则；样式警告基线 1 → 12（全部为盲区真命中，见上git:调试历史）。
- Doxygen 规则细节：类/枚举/函数/方法声明首行（range start = 返回类型/template 之下的
  声明起算行）正上方须紧邻非空 `/** */` 块；真相源 = 接口声明处（impl 里接口已声明函数
  的定义按名豁免）；重载组共用最上方一个块；前向声明与定义间可夹空行（Renderer 先例）；
  template 引入行可跳过（注释挂 template 上方）。decl+def 折叠：method 出类定义不重复
  emit（旧 dump 不 emit 行为保持）、自由函数 decl+def 两条都查。
- 样式规则（判定与名单见 rules_metrics/rules_text/config.py）：①文件 >500、②函数 >120、③认知
  复杂度 >15（SonarSource 风格，lambda/成员函数独立计分；算法 = clangbind）、④接口瘦身
  （非 _impl 函数体 >100 → 迁 xxx_impl.cppm）、⑤成员命名（_/m_ 前后缀）、⑥分层/模块
  优先（零 entt 名单/禁止边/禁 .h/.hpp/内部头 #include/入口 main 模块）、⑦GMF STL 白名单
   （只许 ranges/filesystem/chrono）、⑧禁用旧式 Vulkan API（剥注释 + 标识符边界匹配
   `FORBIDDEN_VULKAN_APIS`，防 bindPipelineToAsset 误报；含经典输入装配——vertex/index
   绑定与 `VkVertexInput*` 族，mesh shader 路线 2026-09-24 封死；token 尾 `*` = 前缀
   匹配族，覆盖 sync2 变体 `vkCmdBindVertexBuffers2`，同时防误伤现代机制
   `vkCmdBindDescriptorBuffersEXT`——名单注释有红线）。①-⑤ 消费 parse 指标，⑥-⑧
   纯文本主进程直读。
- 并发/内存：ctypes 持 GIL → ProcessPoolExecutor 一进程一文件（默认 min(cpu,4)，
  每进程 ~550MB）；CXIndex 每 worker 一个且**永不 disposeIndex**（modules+Indexer 场景
  dispose 必段错误，坑 7 附赠）。
- 既有坑索引（勿回退，细节在各文件头）：C API 不展开 @.modmap（内联展开 + BMI 转绝对）、
  输入文件/驱动路径不进 argv、Gentoo 须显式 `-resource-dir`、BMI 加载失败 → parse NULL
  （按跳过+警告）、LLVM 22 结构体布局（CXCursor 32B / Location/Range 24B / CXToken 24B
  值类型 / **CXIdxDeclInfo 128B 非旧例程 120B**）、TOK_COMMENT=4 非 5（v5 修正）。

## RPC 调试通道（Phase 10b 批 11b.2，loopback HTTP POST）

> 计划/决策 = `docs/phase10b_plan.md`（D9–D12）；本段是稳定形状速查。
> 门 `diagnostics.rpc` **默认 false**（零行为变化，画面 BIT-IDENTICAL），与 `imgui` 门
> 完全独立 → **headless 也可用**（agent 远程调参/截图的主要姿势）。

**分层（依赖方向单向）**：`debug_rpc` = 传输层（`debug_rpc.cppm` 接口 +
`debug_rpc_impl.cppm` pimpl 体，`<httplib.h>`/`<nlohmann/json.hpp>` 只活在 impl 的 GMF），
**零 ECS 零协议、不 import ecs**（函数注入，同 `ConfigReloadHook`/`PickingHook`）；
`debug_rpc_exec` = 协议执行 + 装配（唯一同时认识 ECS/渲染器/协议的 RPC 侧模块，
main 只留一行 `wireDebugRpc(...)` 调用）。**ecs/相机/param 不得反向 import `debug_rpc`**。
`debug_rpc_burst` = `/shotburst` 协议里**与设备无关**的判据（请求体形状 + 绝对帧号锚点裁决，
债-89）；拆出来的理由 = 宿主是 app 层大文件，而这两段是纯逻辑，得能在 `just test` 里逐条钉死
（`tests/test_burst_protocol.cppm`），归 `RGL_BASE_MODULE_SOURCES`。

**线程/时序模型**：

```
HTTP 线程（httplib::Server 连接线程）
  请求 → [mutex] 队列 {RpcRequest, shared_ptr<promise>} → future.wait_for(超时)
渲染线程（唯一碰 registry/Vulkan 的线程）
  renderSystem 帧首 configReloadTick → ConfigReloadHook.poll 组合链
    └→ DebugRpcServer::poll()
         ① drain 队列 → applier(闭包：registry/assetTable/renderer) → resolve
         ② 结算上帧挂起的 /shot（hasFrameCapture → writeCapturePng → resolve）
  → system 链（camera/projection/renderlist）→ requestFrameCapture → drawFrame
```

`configReloadTick` 在 **system 链之前** → `/camera`、`/param` 套用后**本帧即生效**；
`/shot` 帧首收单 → 本帧录回读 → **下帧**帧首结算（响应含 PNG 绝对路径）。
**`RpcResponder` 可跨帧持有**：`resolve` 幂等（重复兑现吞 `future_error`），
持有方析构未兑现 = 等待方拿 `broken_promise` → 503。

**协议（全 JSON、UTF-8、`127.0.0.1:8788`）**：

| 端点 | 请求 | 响应 |
|---|---|---|
| `GET /` | — | `{"ok":true,"routes":[...],"frame":N}` |
| `GET /state` | — | `{"ok":true,"frame":N,"camera":{mode,position,target,yawDegrees,pitchDegrees,up,fovDegrees},"pages":[{name,entries:[{kind,label,min,max,speed,value}]}]}`；kind ∈ `slider\|int\|color\|drag3\|text` |
| `POST /camera` | `{position?,target?,yawDegrees?,pitchDegrees?,up?,fovDegrees?,mode?}` 任意子集 | `{"ok":true,"camera":{...套用后姿态}}`；缺字段不改；角度一律**度**（同 `camera.lua` 的 `fovDegrees`） |
| `POST /param` | `{label,value,page?,material?}`；value = 数字或 `[r,g,b]` | `{"ok":true,"label":…,"value":…}`；未知 label → 404，类型不符 → 400 |
| `POST /shot` | `{file?,gbuf?}`（缺省 `screenshots/rpc_<n>.png`；gbuf ≥0 = G-buffer 诊断通道） | `{"ok":true,"file":绝对路径}`；帧边界 10s 未到 → 504 |
| `POST /shotburst` | `{dir,n(1..1024),prefix?,gbuf?}` | `{"ok":true,"count":N,"files":[绝对路径…]}`；**连续 n 帧**（下一张由帧首结算钩子自登记 ⇒ 第 N..N+n-1 帧，与 HTTP 时序无关）；整批交齐才应答，超时 120s。时域差分**只准用它**采集（`/shot` 逐张拍相邻两张不是相邻两帧）→ `docs/taa_plan.md` §7 第 8 条 |
| `POST /quit` | — | `{"ok":true,"frame":N}`；置 `AppExit.requested` ⇒ **下个帧边界**正常收尾退出（与用户关窗完全同一条路径，应答先兑现再置位）。自动化测试收尾用它，别 SIGTERM 杀进程——那会打断 present/in-flight 且拿不到帧循环之后的 profiler 收口输出 |

错误通例：body 非法 JSON → 400；类型/字段不符（json 异常）→ 400；未知路由 → 404；
`llm_debug` 截图在跑时 `/shot` → **409**（防抢帧卡死 llm 退出）；停机/超时未决 → 503/504。
**超时表**：`/shot` 10s、其余 2s（帧边界没跑到就撤单 + 504）。
**`material` 语义**：先写 `DebugPanelState.materialSel` 再重建页 → 该次写入作用于目标材质。

**批 11.0e 补两项**（自 AGENTS.md 迁入，2026-10-01 瘦身）：① `POST /camera` 传 `target` 时
fps 模式**反推 yaw/pitch**（`cameraAimAt`，与 `readCameraPlacement` 同约定）而非拒绝，
显式给角度则尊重显式值；② 启动在 bind 前用 httplib Client **探测**（1s 超时），连得上 =
已有监听者 → error + 不启动（`SO_REUSEPORT` 会让多实例静默共存）——故 RPC 起跑前仍须
`pgrep -cx rgl` 确认无残留。

**装配与停机**：main 末尾一行 `auto debugRpc = wireDebugRpc(registry, assetTable,
backEnd.renderer, pre.llmEnabled);`——**声明序在 registry/assets/backEnd 之后** = 析构序其先，
try 块退出时 `~DebugRpcServer = stop()` 先于 registry 销毁（闭包里的裸指针绝不越权），
**`main()` 不显式 `stop()`**（RAII 收口，不占认知复杂度预算）。门关 / bind 失败（端口占用）
都**降级返回 nullptr**，只日志不崩。`stop()` 顺序 = 先 503 结算在途 → 关监听 → join。

**配置键**（`configs/diagnostics.lua`）：`rpc = false`、`rpc_port = 8788`（越界回落 8788）。

**两个已修的坑**（详见 `git:调试历史` 2026-09-28 条）：① httplib 对**所有** ≥400 都回调
`set_error_handler` → 必须只补空体，否则自产 4xx 载荷被盖；② `rpcDispatch` 不得把
responder move 进下层（catch 分支会拿到空句柄 → 恒 504），传拷贝。
