## 2. 排查过程中已确认并修掉的 bug

这三个都是**真 bug**，与场景无关，可以独立采纳。

### Bug 1：级联选级把片元推进未写入的槽（已修，未提交）

采样端选级是三段**无条件**比较（`rgl/shaders/shadow.slang`）：

```slang
if (distSq > splits.x * splits.x) cascade = 1u;
if (distSq > splits.y * splits.y) cascade = 2u;
if (distSq > splits.z * splits.z) cascade = 3u;
```

CPU 侧只填生效级（`render_list_impl.cppm` 的 `fillShadowData`）。生效 1 级时
`splits = {1e9, 0, 0, 0}`，后三槽是 0，而任何真实片元 `distSq > 0` 恒成立
→ **两级判断全部命中，cascade 被推到 3**，而 3 号槽的矩阵从未被写过（全 0）
→ `clip.w = 0` → `ndc = 0/0 = NaN` → 阴影因子恒 0。

**此 bug 与机位无关**——意味着 5a-3 / 5a-4 判定的"阴影可见"和那四组基线 md5
都是在坏状态下测的，需要作废重测。

修法：未生效的槽也填 `kNoFar`，让片元永远选不到没写过的槽（shader 侧无需知道生效级数）。

### Bug 2：拟合球的平面约定与球算法不一致（已修，未提交）

`extractFrustum` 与 `sphereInFrustum` 用的都是 **"内侧 = dot(n,x) + w ≥ 0"**，
但 `frustumBoundingSphere` 里的 Eberly 增量法是 **"≤ 0"** 那套写法。
两套混用会让 `center += n * (dist - radius)` 把球心推向**内侧深处**——与所需方向相反，
半径永远长不大，算出的球装不下视锥。

实测：近距离机位算出 `r = 1.25`，而该视锥远平面角点距球心 2.0。
视锥边缘的建筑整批落在球外 → 被逐级剔除丢掉 → 阴影图整幅 clear。

修法演进（**注意中间试错过，别重走**）：
1. 先试"把平面取负转成 ≤ 0 约定"→ **半径被直接推成 0，更糟**；
2. 最终改成 **8 角 → 世界 AABB → 外接球**，不依赖任何符号约定。
   该函数自己的文档契约就是"保证整个视锥在球内，**不追求最小球**"，AABB 法正好对上。

### Bug 3（架构修正，已改未提交）：剔除体与拟合体解耦

原来剔除用"图元世界球 × 级联切片球"，与 Filament 的做法不符。现按
`rgl/scene_context.cppm` 新增的 `ShadowVolume` 重做：

- 盒的 **XY** 由该级切片球定（紧，只覆盖受光面）
- 盒的 **Z** 覆盖**全部投影体**的世界 AABB 在光轴上的投影
- 剔除改判"图元世界球投到光空间后是否与盒相交"（`casterInShadowVolume`）
- 实体遍历拆成两段：**循环内攒候选** → **循环后建体再逐级剔除**
  （盒的 Z 界依赖全部投影体，顺序上必须先知道盒才能判"谁在盒内"）

依据见 §4。

## 3. 当前卡点：拟合球对所有机位返回半径 0（**已解决，见文末 §8**）

`frustumBoundingSphere` 改 AABB 法后，对上述机位**仍返回半径 0**，
因为 8 个角里全部 `clip.w <= 0`，走了退化返回：

```cpp
if (clip.w <= 0.0f)
    return Bounds{glm::vec3{0.0f}, 0.0f};  // 角点落在相机后方 = 退化视锥
```

诊断日志打出的关键数值（临时加的，已撤）：

```
[SHDBG] cands=1591 drawn c0=42 xyR=0.000 t=[0.000,0.000] eyeOff=0.000 shadowPass=1
```

`xyR = 0` → `buildShadowVolume` 走 `radius <= 0` 早退 → 光空间体全零
→ 1591 个候选只有 42 个（碰巧轴心附近）过了剔除 → 阴影图几乎整幅 clear → 对拍 0.000%。

### 已排除

- **手性**：`view = glm::lookAt(...)`（`camera.cppm:175-176`，右手系看向 −Z）、
  `proj = glm::perspective(...)`（`ecs_impl.cppm:270`，GLM 零到一）。标准组合，`clip.w` 应为正。
- **`projWithDepthRange` 的系数公式**：按 `ndc.z = -A - B/z_view` 反推，
  要求 `A = f/(n-f)`、`B = A·n`，与该函数当前写法一致。

### 最大嫌疑：GLM 的列主序下标

`projWithDepthRange`（`rgl/scene_context.cppm`）：

```cpp
glm::mat4 out = proj;
const float A = newFar / (newNear - newFar);
out[2][2] = A;
out[3][2] = A * newNear;
```

GLM 的 `m[col][row]` 是**列优先**（`m[2][3]` 才是"第 3 行第 2 列"）。写这两个下标时
**必须逐一核对它们落在 `clip.z` 还是 `clip.w` 上**——`clip.w` 的 z 系数是另一个元素
（GLM 源码里写作 `Result[2][3] = -1`），本函数**没有碰它**。

要确认的两件事：

1. 用项目真实的 GLM 头写探针：`glm::perspective(45°, 16/9, 0.05f, 2.197f)`，
   打印 `proj[2][2] / proj[2][3] / proj[3][2] / proj[3][3]`，
   再对 8 个 NDC 角点算 `clip = proj * corner`，看 `clip.w` 与 `clip.z`。
2. 确认 `GLM_DEPTH_ZERO_TO_ONE` 下 GLM 自己的 `A`、`B` 到底是什么
   （我按记忆推的，与手头代码对不上，**不要信记忆，用探针**）。
   项目里已有同类探针先例：`/tmp/opencode/glmprobe/probe3.cpp`（已随 /tmp 清掉，
   思路是链项目真实 GLM 头 + g++ 单独编译）。

## 8. 收口（2026-09-29 同日）：§3 卡点的真根因与"最大嫌疑"平反

**§3 的"最大嫌疑"（GLM 列主序下标）经探针实测洗清**：`projWithDepthRange` 写的
`out[2][2]/out[3][2]` 与 GLM `perspectiveRH_ZO` 源码的 `Result[2][2]/Result[3][2]`
完全对应，w 行未动。真根因在 `frustumBoundingSphere` 自己身上，两条叠加：

1. **8 角循环把 NDC 角点 `(±1,±1,±1,1)` 当世界点乘了正向 `viewProj`**——NDC 回世界
   必须乘 `glm::inverse(viewProj)`。正向透视矩阵 w 行恒 `(0,0,-1,0)`，远平面角 w=−1
   恒负 → 命中 `clip.w <= 0` 早退 → 半径恒 0。所谓"退化视锥保护"实为错误构造的遮羞布。
2. **本项目 GLM 编译为 depth zero-to-one**（`rgl/CMakeLists.txt:105`
   `GLM_FORCE_DEPTH_ZERO_TO_ONE`），NDC z 值域 `[0,1]`——角点 z 应取 {0,1}。
   只修①不修，近角 w 恰为 0（`0.0 <= 0.0`）仍触发早退。

修法与验证（探针 `/tmp/opencode/glmprobe/probe.cpp`，链项目真实 GLM 1.0.3 头）：
`invViewProj * (±1,±1, z∈{0,1}, 1)` → 世界 AABB → 外接球；复现机位 r=2.4017 ≥
远角距 2.0074（包住 ✓）。落地后开关对拍 **21.5% 像素、全变暗 0 变亮**（复现机位），
树冠/建筑/灯柱投影形状正确；四组基线重测与 D1 复测 → `git:调试历史`
