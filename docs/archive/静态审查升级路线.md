# 静态审查升级路线（LLVM 23 + Lifetime Safety）

> **状态**：调研（2026-09-24 定稿，**尚未实施**——前置是系统 LLVM 23 落地。原文写的"预计 ~20
> 天内"已失效：2026-10-14 复核本机 clang 仍 22.1.8、全仓无 `-Wlifetime-safety` 开关，别再拿那句
> 当排期）。记录相对 Rust 默认静态检查的差距结论、clang lifetime 分析现状、以及两阶段落地计划。
> 触发场景：升级编译器、开 `-Wlifetime-safety`、改 `tools/checks` clangbind 时先读本文。

## 1. 背景：与 Rust 借用检查的差距

对照「Rust 默认」（borrow checker + clippy + cargo test），本项目静态检查现状：

| 维度 | 现状 | 差距性质 |
|---|---|---|
| 架构/风格规则 | `tools/checks` 全套（partition/docs/现代 C++/ECS 分层），带缓存+并发+`--strict` | **不弱于** clippy 默认（规则是项目定制的） |
| 内存安全（生命周期半边） | 仅 `-Wall -Wextra`（含 statement-local `-Wdangling-gsl`），**无跨语句 Loan/Origin 分析** | **主要差距，本路线图要补的** |
| 内存安全（排他性半边：`&mut XOR &*`） | 无 | **补不上**——见 §2 |
| 动态兜底 | 无 ASan/TSan 常态化 | 可选后续 |
| 测试/CI | 无单测、无 CI | 独立工程债，与本路线正交 |

**结论**：静态检查上对 Rust 最大且可部分弥补的差距 = 借用检查。其中「悬垂指针/生命周期」部分
可用 clang 23+ 的 Lifetime Safety Analysis 补到约六七成价值；「排他性/迭代器失效靠 alias 约束」
部分是语言设计问题，C++ 事后补不上。

## 2. 什么补不上（预期管理）

Clang lifetime RFC 明确 **不做强制 exclusivity（alias-xor-mutability）**，且 C++ 迭代器习惯
（同容器多个 non-const iterator）与 Rust 借用规则结构性冲突，社区无增量推广计划。
Google Crubit 的 lifetime annotations 方案同样自认 "not a borrow checker"。

因此本路线的验收目标是：

- ✅ 跨语句/跨作用域的 use-after-scope、use-after-free、返回栈地址、dangling-field、
  容器失效后使用（部分）——`-Wlifetime-safety` 覆盖面
- ❌ 全量借用检查语义（排他可变、数据竞争编译期排除）——不承诺，数据竞争靠未来 TSan 动态兜底

## 3. 现状核查（2026-09-24）

- **编译警告面**：`CMakeLists.txt` 仅 `-Wall -Wextra` + `RGL_WERROR`（默认 ON → `-Werror`）。
  全文无 `-Wlifetime-safety`、无 `lifetimebound` 注解。
- **本机工具链**：clang **22.1.8**（Gentoo `/usr/lib/llvm/22`）。`-Wlifetime-safety` 在 22 上
  报 `unknown warning option`——该分析 **Clang 23 才落地**（23.1.0 起有正式文档，24 持续增强）。
- **Gentoo 树**：`llvm-core/clang-23.1.2` ebuild 已可见；world 更新中的
  `llvm-common-23.1.2` 只是公共文件包，**不含 clang 本体**。要显式
  `emerge llvm-core/llvm llvm-core/clang llvm-core/lld`。
- **Windows**：AGENTS.md 钉 LLVM 22——升级后双平台版本会分叉，flag 必须按编译器探测门控。

### clang 23 lifetime 分析要点（调研摘要）

- 设计 inspired by Polonius（Rust 借用检查器的继任者），Loan/Origin 数据流、过程内分析。
- 零注解可跑；`[[clang::lifetimebound]]`、`[[gsl::Owner]]`/`[[gsl::Pointer]]` 注解提升跨调用精度，
  还带 fix-it 自动推断注解。
- 分级启用：`-Wlifetime-safety-permissive`（高置信，建议起步）⊂ `-Wlifetime-safety` ⊂
  `-Wlifetime-safety-all`。
- 旧的 statement-local 检查 `-Wdangling-gsl` 在 clang 22 已有（`-Wall` 默认含），只能抓单语句内悬垂。

## 4. 两阶段落地计划

### 阶段 1：升 LLVM 23 + 工具链回归（前置，与 lifetime 无关）

1. 系统侧（手动，sudo）：
   `emerge -auDN @world --exclude sys-firmware/edk2-bin`（edk2-bin 与 qemu-10.2.3 的
   `qemu_softmmu_targets_x86_64` USE 冲突已知，短期内 qemu 不升级，跳过即可）；
   再显式 `emerge llvm-core/llvm llvm-core/clang llvm-core/lld` 拉 23.1.2。
2. 确认 `clang++ --version` = 23.1.2（Gentoo symlink/eselect）。
3. **BMI 跨版本不兼容**：`just clean-all && just config && just build` 全量重建。
4. `just checks --strict` 全量回归，盯两类翻车点：
   - **`clangbind.py` ABI**（最高风险）：ctypes 绑死 LLVM 22（CXCursor/Indexer 结构体
     sizeof、kind 拼写实查值、`clang_getRange` 更名坑）——23 下须重实查一遍，
     **禁止凭记忆改数值**；docstring 里的「LLVM 22 实测」字样同步更新。
   - **doccheck `-ast-dump` BMI 竞态**：clang-22 有 SIGSEGV 前科（调试历史 2026-09-14）；
     23 下观察是否复发，复发不阻塞（skip 回落语义已有）。
   - resource-dir：`cmdclean.py` 实际走 `-print-resource-dir` 动态取，预期自动适配；
     注释里写死的 `/usr/lib/clang/22` 顺手改掉。
5. Windows 暂留 LLVM 22，AGENTS.md 记录版本分叉；flag 探测保证 22 下不炸（见阶段 2 第 1 步）。

**回滚**：esentinel/eselect 切回 22 + `just clean-all` 即可；`clangbind.py` 改动独立 commit 便于 revert。

### 阶段 2：开 `-Wlifetime-safety`（阶段 1 稳定后）

1. **探测式挂载**（`CMakeLists.txt`，不动 Justfile）：
   `check_cxx_compiler_flag(-Wlifetime-safety ...)` 成功才 `add_compile_options`；
   Windows/LLVM22 自动落空。首开只挂 **`-Wlifetime-safety-permissive`**，**不进 Werror**。
2. 全量编译收集告警 → 逐条三分类：
   - 真 bug → 修；
   - 缺注解 → 补 `[[clang::lifetimebound]]` / `[[gsl::Owner]]`/`[[gsl::Pointer]]`
     （优先吃 fix-it 推断）；
   - 误报/不可判 → 定点 `-Wno-`，进 `CMakeLists.txt` 有意抑制注释区（仿现有
     `main-attached-to-named-module` 先例），**禁止全局关**。
3. 存量告警清零后（复刻 2026-09-24 `-Wall -Werror` 清零路径）：
   permissive → 全量 `-Wlifetime-safety` → 进 `RGL_WERROR` 面。
4. 可选加固（独立小项，不阻塞）：
   - `tools/checks` 文本规则：禁裸 `new/delete` 配对、返回成员引用须 lifetimebound；
   - Debug CI/本地加 ASan/UBSan 跑冒烟（动态兜底，与静态互补）。

### 明确不做

- 自研借用检查/排他性分析（语言层问题，tools/checks 也不适合做数据流分析）；
- 无条件在 Windows LLVM 22 上加 flag；
- 未清零先 `--strict`/Werror（会把构建面打红，违背「先警告后红线」惯例）。

## 5. 触发与维护

| 事件 | 动作 |
|---|---|
| 系统 clang 升 23 | 走阶段 1 全流程；`clangbind.py` 单独验证 commit |
| 开 lifetime flag | 走阶段 2；告警清零记录附本文或调试历史 |
| clang 24+/Windows 升级 | 重跑阶段 1 第 4 步（clangbind 重实查 + checks 回归） |
