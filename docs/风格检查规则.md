### 1.7 全仓文档指针有效性（`doc_pointer_checks`）

- **判定**（四条，均 error 级）：

  | # | 判什么 | 形态 |
  |---|---|---|
  | ① | **悬空** = 文本里写出的 `<项目目录>/**.md` 磁盘上不存在（含 `*` 或 `~` 的写法是模式不是路径，跳过） | 全文本（不限反引号） |
  | ② | **退役** = 出现 `config.RETIRED_DOC_NAMES` 里的文件名（裸名或带目录都算），消息里直接给出**现在的归宿** | 全文本 |
  | ③ | **反引号内的项目路径**（债-111）= `` `tools/x/` `` / `` `rgl/x.cppm` `` / `` `docs/<某文档>.md` `` / `` `x.cppm` `` 磁盘上不存在 | 反引号片段 |
  | ④ | **反引号内的命令名**（债-111）= `` `just <配方>` `` / `` `imgqa <子命令>` `` 的第二 token 不在真相源（Justfile 配方行 / `cli_table*.cpp` 注册表）里 | 反引号片段 |

- **与 §1.6 的分工**：§1.6 只对账 `AGENTS.md` 一个文件（开机路由表）；本条把同一判据铺到**全仓文本**
  ——含 `rgl/*.cppm`、`tests/`、`configs/*.lua` 的注释，文档指针有一半住在代码注释里。
- **动机**（2026-10-08 删除全局调试时间线文档）：那份文档被 70+ 处引用，删完文件留满仓悬空指针 =
  后来者按指针找不到东西，**比从没有过指针更贵**（会被读成"是我没找到"）。而删文档最容易复发的形态
  是从 git 捞回来重建一份——那时指针反而"有效"了，故退役名单单独点名，不靠悬空判定。
- **③④ 的动机**（债-111，2026-10-12 给 `docs/mdi_plan.md` §18 记账时自查当场抓到）：①② 只查
  `.md` 路径，**反引号里的文件名 / 目录名 / 命令名不在射程内** ⟹ 凭记忆编造的 4 个名字
  （`tools/meshlet_gen/`、`meshlet_cluster_data.generated`、`addAlphaShadowEntry`、
  `mdi_selftest --check`）外加不存在的 imgqa 子命令 `shadow_lod` 一路零警告。
- **③ 的覆盖形态**：含 `/` 且首段是项目根（`config.DOC_POINTER_PATH_ROOTS`）的斜杠路径 +
  以项目自有扩展名结尾（`config.DOC_POINTER_BARE_EXTS`：`.cppm` `.slang` `.md` `.lua` `.cmake`
  `.py`）的裸名。`x.cppm:12-30` / `x.cppm::Sym` / `docs/<某文档>.md §段` 先截到路径为止——**符号存在性
  是台账明写的第二步**（要 grep/ctags 兜底，误报面大）。
- **③ 的排除形态**（每条都有实测误报作依据，**别当保守删掉**）：含空白或 `=`（命令行、配置键、
  散文）；含通配/占位（`docs/*.md`、`aa_coverage.{h,cpp}`、`<项目目录>`）；含 `xxx`（示例占位）；
  斜杠路径首段不是项目根（`vulkan/vulkan.hpp`、`github.com/…`、`~/…`，以及 `build/…`——构建产物
  随机器漂，拿它判存在性 = 造"换台机器就红"的假判据）；中间段带扩展名（`rgl/diagnostics.cppm/_impl.cppm`
  是「主接口 + 实现单元」**两个文件**的简写，本仓 7 处）；裸名扩展名不是项目自有（`.h`/`.hpp`/`.cpp`/
  `.glsl`/`.json` 的裸名大量指**上游与 SDK 文件**：`ShadowMap.cpp` = Filament、`vulkan_core.h` = SDK、
  `callbacks_glsl.h` = FSR vendor，实测 100+ 条，且没有"上游文件白名单"这种不漂的真相源可写）；
  裸名以 `_` / `.` 开头（`_impl.cppm`、`_schema.lua`、`.manifest.json` 是**命名模式**不是文件）。
- **④ 只做两条命令**：`just` 与 `imgqa` 有机器可读的真相源（配方行正则 / `SubcommandSpec{` 表），
  零歧义。不做"任意命令名存在性"——实测含空格的反引号片段 2872 处、首 token 755 种，绝大多数是
  公式与代码片段（`if (flag)`、`gate = saturate(2 − motion)`），没有不漂的外部命令白名单可写。
  ⚠ 真相源解析两次实测**差点让规则说谎**：Justfile 配方正则写成 `[^:=]*` 排除变量行（那是"既不含
  `:` 也不含 `=`"，`test *ARGS=""` 里的 `=` 把 34 条配方吃掉 16 条，真配方被报成"没有这一条"）；
  imgqa 注册表只指 `cli_table.cpp` 单文件（拆过 TU，漏 `diffstruct` / `diffblock` 两条真子命令）。
- **存量走棘轮**（机制先例 = §6.1 的 `byte_offset_baseline.json` 与 `tool_baseline.py`）：命中按
  文件记进 `tools/checks/doc_pointer_baseline.json`，**只准降不准升**——新增一条 = 有人凭记忆写了
  不存在的名字，处置是改指针，不是去基线登记额度。清掉一批后收账：

  ```bash
  python3 tools/checks/main.py --update-doc-pointer-baseline   # 先确认没有新写的假指针再用
  ```

- **要写一个「故意不存在」的名字时不要用反引号**（2026-10-14 补）：记误诊、记"当年写过的错路径"、
  记"计划中尚未落地的文件"这三类散文，本身就要点名不存在的东西——用「」或引号写，别用反引号。
  理由：③④ 只看形态不看语气，"这个文件不存在"句子里的文件名一样命中；而台账（`docs/还债总账.md`）

  比多写一条 error 贵得多。行级豁免没有做（做了就等于给"我确定它不存在"发通行证，而这句话恰恰是
  本规则要防的那句话）；文件级只免 `config.DOC_POINTER_EXAMPLE_FILES` 一条（规则全景文档必须原样

### 1.8 判据契约表的出处指针有效性（`judgments_pointer_checks`）

- **判定**（均 error 级）：判据表（`config.JUDGMENTS_TABLE_GLOB`，在 `tools/imgqa/` 内 glob）里
  `tools/imgqa/<文件>` 紧跟 `` `标识符` `` 或「段名」的写法，① 目标文件磁盘上不存在 → 报；
  ② 锚点（剥掉 `()` 与 `::` 右半）不在目标文件文本里 → 报，消息**直接列出当前真正含该锚点的文件**。
- **与 §1.7 的分工**：§1.7 管「`.md` 路径存不存在」，铺到全仓；本条管**「文件还在、锚点没了」**——
  这种失效 §1.7 查不到（路径确实存在），却同样让人按图索骥翻空。范围只圈判据表本体：判据表的职责
  就是钉住 imgqa 自己的仪器口径，它的「钉住：…」字符串会被 `imgqa check` 原样打印出来。
- **动机**（2026-10-11，imgqa 拆 TU 那批）：把 `temporal_motion.cpp`（2748 代码行）按仪器拆成 13 个
  TU 之后，判据表里 **18 处**出处指针全部指向"文件还在、符号已搬走"的位置，而 `imgqa check`
  与样式闸门**全程绿**。拆文件是本项目的高频动作，这条不落成护栏就必然复发。
- **实测**（落地当天）：现状 **0 条**（18 处指针已随批修完）。⚠ 本条**差点假绿**：第一版把
  `glob` 写在仓库根上，扫描面为空 ⟹ 永远报 0，而"0 条"看起来正是"规则通过"。补上阳性锚点

### 2.1 零违规回归护栏（剥注释后 token 级）

| `goto` | 0 | 现代控制流 |

### 2.2 `new` / `delete` 表达式（分配器/C API 豁免）

- **判定**：剥注释后匹配 `new <type>` 分配表达式与 `delete` 表达式（`= delete`
  特殊成员删除不命中）。
- **豁免名单**：`NEW_DELETE_EXEMPT = {rgl/VmaBuffer.cppm}`——`shared_ptr` 控制块
  `new AllocatorControlBlock` + deleter `delete p`（分配器 RAII 唯一合法 raw 新建点）。
- **实测**：全库仅 `VmaBuffer.cppm:293/297`。

### 2.3 `throw` 折中版 A：返回 `std::expected` 的函数禁 `throw`

- **决策**（2026-09-24）：严格版「仅构造函数可 throw」需迁移 ~80 处启动期
  `std::runtime_error` fail-fast，与现行双通道（启动 throw / 运行 expected）冲突，
  **不采用**。折中版 A = **API 已选择 `std::expected` 的函数体内不得再 `throw`**
  （防双通道混用：调用方按 expected 契约处理，异常会穿透）。
- **消息**：命中时提示「非构造/启动 fail-fast 路径请改用 `std::expected` 传播错误」。
- **实现**：metrics `functions[]` 增 `returns_expected` / `throws` 两字段
  （签名 tokenize 到首个 `{` 前见 `expected`；体内 AST 游标找 `ThrowStmt`）；
  `CACHE_VERSION` v6→v7。
- **实测**：落地前 **0 处** 双条件命中（88 处 throw 全在 expected API 之外的
  构造/启动 free function）——零违规护栏；构造函数无返回类型天然不触发。

### 2.4 明确不做（本轮）

- 全面禁裸指针成员：大量非拥有观察者（`const T*` + 注释）与 C API 缓冲视图，
  全禁极吵；`new`/`delete` 已覆盖所有权危险面。
- C 风格转换 / `(void)` 丢弃：`(void)` 是刻意 discard；`shader.cppm:24` 的
  `(size_t)tellg` 待单独清理后再立规则。
- `std::copy`/`std::fill`→ranges：点名违规仅 2 处，收益低，暂缓。
- `explicit` 单参构造 / `[[nodiscard]]` 补全：需 metrics 扩展签名属性，另开批次。
- 命名（camelCase/PascalCase）、`k` 前缀常量、GMF 收敛用量分析：未入规范或需 AST。

## 5. 第三轮（批 12.2d）：库分层闭合 `libcore_closure`

引擎拆四库（rlbase/rlgfx/rlscene/rlframe）后，「rlbase 整层无设备依赖」这条性质
原本只活在 CMakeLists 的注释里。本轮把它变成机器可验的断言。
**新文件 `rules_layers.py`，配置项 `LIB_LAYER_LIST_VARS` / `LIB_LAYER_ORDER`。**

### 5.1 问法换了（这是本轮的核心，不是实现细节）

旧问法「这个模块 import 了 Vulkan 吗」**错**在两处：

- `import rlvk` 是**编译期类型依赖**（要 `vk::Format` 这类枚举），`需要一个 VkDevice
  才能跑` 才是**运行期依赖**。两者不等价。`render_graph` / `state_kit` 都 import rlvk
  却一个设备都不碰，它们的纯逻辑在 `just test` 里就能测（事实也已经这么测了）。
- 它只盯 Vulkan 一个名字，抓不到「低层 import 了一个同样不碰 Vulkan 但归属上层的
  模块」这种真正的层级越界。

新问法只有一条，且完全静态可判：

> **一条 import 边，只能从高层指向同层或更低层。**
> `rlbase(0) ← rlgfx(1) ← rlscene(2) ← rlframe(3) ← rgl(4)`

设备依赖不需要点名：`rlvk` / `VmaRaii` / `vulkan_utils` 都住在 rlgfx，低层 import
不到，所以「rlbase 无设备依赖」是这条规则的**推论**。

### 5.2 三条设计约束

1. **真相源 = `rgl/CMakeLists.txt` 的五份清单**，不另立名单。清单改名而配置没跟上
   会让规则**静默失效**，所以读不到清单时报 error 而不是返回空——失效不出声时，
   「零警告」会被读成「分层干净」。
2. **分区实现单元（`module X:impl;`）按主模块归层并且必须扫**。历史上唯一那条逆向边
   `param_pages:impl → ecs` 正是从分区实现单元发出来的；而
   `modern_vulkan_tutorial/.../data/model.json` 那个依赖图工具漏了 90% 的分区实现单元
   import（见 AGENTS.md），本规则从源码正则直抽，不走它。
3. **同层 import 一律合法**，不试图细分同层内部——细分会诱使「为了让分层好看而扭曲
   逻辑归属」，那是拿架构整洁换局部整洁。

### 5.3 验证（三条变异 + 一条阴性）

| 变异 | 期望 | 实测 |
|---|---|---|
| rlbase 的 `camera.cppm` import rlframe 的 `ecs` | 报逆向边 | ✅ `rlbase(第 0 层) import rlframe(第 3 层)` |
| rlbase 的**分区实现单元** `diagnostics_impl` import rlgfx 的 `rlvk` | 报逆向边 | ✅ 覆盖到分区实现单元 |
| `LIB_LAYER_LIST_VARS` 改成不存在的清单名 | 报「本规则未执行」 | ✅ 不静默 |
| 真实代码树 | 0 警告 | ✅ 110 文件 / 5 层（30+22+22+33+3）全部同层或向下 |

`rgl/shaders/**` 的检查由 `cmake/RglChecks.cmake` 的 `shader_dep_check` 目标每次构建跑两个
stdlib-only 脚本（同样默认只警告、`--strict` 才退 1）。**规则语义的唯一真相源是脚本自身的
docstring，本文不抄**：R1 import 闭包 / R3 StructuredBuffer 契约 / R5 裸字节偏移棘轮 /

### 6.1 R5 裸字节偏移棘轮（批 G，2026-10-12）

**为什么**：`sceneData.Load4(721952u)` 这种手写字节偏移把类型在 CPU/GPU 边界擦掉后再手工
物化布局，C++ 侧 `kSceneData*Offset` 与 shader 侧各写一份 = 双源。R5 的唯一目的：让这种形态
**只能减不能增**（判据出处 → `docs/constantbuffer_迁移计划.md` §5.2）。

**判据两条**（缺一条就大面积误报，两条都在 `tools/check_shader_deps.py` 里）：

1. 接收者**声明类型**是 `ByteAddressBuffer` / `RWByteAddressBuffer`——纹理也有
   `tex.Load(int3(p, 0))` / `tex.Store(gid, v)`，按函数名判会把它们全禁了；
2. **第一个实参**（字节偏移所在位）含**裸十进制字面量**——`Load<T>(i * sizeof(T))` 与
   `Load4(base)` 是迁移的**目标形态**，必须放行；`Store(o, 0u)` 的 `0u` 在写入值位上，
   不是偏移，所以只看第一个实参。

**棘轮**：存量按文件记进 `tools/checks/byte_offset_baseline.json`（按文件而非全局一个数，
否则「A 迁掉 3 条、B 加 3 条」互相抵消）。上升 = ERROR，下降 = 警告并打印收账命令：

```bash
python3 tools/check_shader_deps.py --update-byte-offset-baseline   # 迁移掉一批之后收账
```

🔴 基线文件缺失 / JSON 坏 / 格式不符 ⟹ ERROR 且声明「本次未做任何对账」——这里**故意比**
`tool_baseline.load_baseline`（缺失→空表按未登记）更严：空表会被下游读成「零违规」= 假绿。

**已知射程外**（汇总行出声，别读成「0 条违规」）：`Interlocked*` 同样吃字节偏移但未纳入
棘轮；偏移字面量先存进变量再传参（`const uint o = 48u; buf.Load(o)`）看不见——棘轮数的是
「调用点内联字面量」，不是「字节偏移总量」。

### 6.2 注释剥离必须是单遍扫描（R1/R3/R5 共用 `strip_comments`）

`//` 与 `/* */` 互相嵌套时，**两种「两条正则、分先后」的顺序都会误吞真代码**。本项目踩的是
「先块后行」：行注释里写 `configs/*.lua` 含 `/*`，被当成块注释起点一路吞到下一个 `*/`，
`taa.frag.slang` 一次少扫 224 行（R5 变异实验暴露：往该区间塞一条 `Load4(12345u)`，旧实现
报 0 条 = 假绿，新实现抓到）。字符串字面量里的 `//` 同理要跳过。实现与回归说明 →
`tools/check_shader_deps.py::strip_comments`。

### 6.3 R6 sceneData 全区字节读禁令（批 N+1，2026-10-13）

**为什么**：scene data 类型化迁移（`docs/constantbuffer_迁移计划.md` §9）把 `ByteAddressBuffer
sceneData` + 手写字节偏移这条旧路逐区搬空，批 N+1 删掉声明本身。R5 是**棘轮**（别的
ByteAddressBuffer 允许有裸偏移，只准减），**盖不住"把 sceneData 这个名字加回来"**——基线里
`scene.slang` 已经是 0 条，加回来只是又变 0 条以外的新文件条目，甚至可能被同批的其它下调抵消。
R6 因此是**绝对禁令**：只认 `sceneData` 这一个名字，没有基线、没有豁免、没有下调命令。

**判据**（语义真相源 = `tools/check_shader_deps.py` docstring R6 节）：剥注释后的
`rgl/shaders/**.slang` 出现 `ByteAddressBuffer sceneData` 声明或 `sceneData.Load*/Store*`
= **ERROR**（不是警告：这条没有存量要棘轮，命中即回归）。⚠ 禁的是"绕过类型化载体按字节读它"
这条**旧路**，scene data 的**物理 buffer 仍然存在**（12 条子范围描述符指进它各区）。

🔴 **自检先于判据**（形态先例 = §6.1 末的「基线不可用 ⟹ 声明本次未做任何对账」）：一条
"什么都没找到"的规则与一条"扫错了目录"的规则**输出一模一样**，所以先要求扫描面里确实有
`scene.slang`（sceneData 曾经的唯一声明地 = 这条规则唯一可能咬人的文件），看不见它 ⟹
ERROR「本次未做任何对账」。

| B R6 扫描面置空（模拟"规则空转"） | ERROR「R6 本次**未做任何对账**：扫描面（现 0 个 .slang）里没有 scene.slang」；`--strict` **退 1** |

**为什么 R5/R6 都盖不住**：R5 数的是**裸偏移字面量条数**，于是「先声明一个还没有偏移的

### 7.1 与构建开头 `reflection_check`（SHA1 护栏）的分工——本规则的立论全在这里

`cmake/ReflectionManifest.cmake` 只哈希**输入**（`.slang` + `_schema.lua` + `.inja`），
它守「改了输入忘了 `just reflect`」。三类它**结构上看不见**的漂移才是本规则的射程：

1. **生成物被手改**——manifest 里没有产物的哈希（实测：把 `offsetof(ModelVertex, uv)` 从 24
   改成 20，`reflection_check` 照常「检查反射输入哈希」通过）。
2. **`constants` 段反射根本不校验**（`tools/generator.cppm` 原话「反射端无对应数据，直接由
   schema 声明生成」），而 schema 常量真正的消费者常常是**另一枚不在该管线输入清单里的着色器**
   ——`model_schema.lua` 的 `kTrianglesPerGroup` 被 `model.mesh.slang` / `shadow.mesh.slang` /
   `izb_mask.mesh.slang` 各抄一份字面量，改它们既不触发 SHA1、也不进反射（实测：改
   `model.mesh.slang` 的 10 → 11，`reflection_check` 全绿）。
3. **`descriptorSlots` 的 binding 号在 slang 反射路径里不校验**——`reflection_tool slang`
   只跑 `validateSlangVertexLayout` / `validateSlangPushConst`（`validateSchema` 属已退役的
   JSON 路径）。schema 写 `index = 24`、shader 写 `[[vk::binding(25, 0)]]` ⟹ 运行期往错的
   堆槽读数据、静默画错。

### 8.1 挂点：为什么是「checks 里一行读数 + `just coverage` 出全表」

`just checks` 每次 `just build` 都跑。两个失败模式各在一侧：

| 挂法 | 死法 |
|---|---|
| 全表进 checks（每次构建都印） | 一张没人裁决的表每次构建都印 = 噪声；噪声判据比没有判据更贵（训练人整体跳过 checks 的输出） |

### 10.1 面 1｜schema ↔ 两份生成物 **三方逐条深度对账**

构建期的 `reflection_check`（`cmake/ReflectionManifest.cmake`）**只哈希输入**——产物被编辑它
看不见（同 §7 `rules_reflection.py` 补的那块盲区）。而本管线一次出两份产物，
"只重生成 / 只手改其中一份"是真实失效形态：两份产物各带一份过期事实，任何单侧对账测不出来。
⟹ 三方按 **顺序 + 逐字段**对账，差异点名到嵌套路径（`shotburst.request.fields[0].max`）、
两侧各是什么。

🔴 **批 2 起 schema 是嵌套的**（`request = { fields = { {name=…, min=…}, … } }`），本模块的
Lua 读取因此从"认深度 1 的扁平 `key = value`"换成**递归下降的 Lua 表解析器**
（`parse_lua_table`）。为什么必须换：旧解析器只认一层，遇到嵌套表会把 `fields = {…}` 整段
读不出来 ⟹ 字段级的对账**根本不存在**，而"零警告"会被读成"三方一致"。换完之后 schema ↔
`.json` 是**整份记录的深度相等**（任意层嵌套），不是逐字段挑着比——挑着比的毛病是新加的键
默认不在比较范围里，那正是"schema 变装饰"的机制版。
解析器**读不懂就抛**（不认的转义、裸标识符、括号不配对、位置键与命名键混用），抛出来算
"出声"而不是"跳过"：静默少解析一块 = 假绿。认的形态与沙箱口径同 `tools/schema_loader.cppm`
的 `loadLuaToJson`（两侧都不许 schema 里写代码）。

顺带钉产物**内部**自洽两处：`RpcRouteMethod::get` 那档必须配 `methodText` `"GET"`；字段名常量

### 10.3 面 3｜每个声明的字段都必须有 `rpc_field::<端点>::<字段>` 引用点（批 2）

面 2 拦"写副本"，这条拦**没人消费**：字段在 schema 里声明了、生成物也出了常量，但处理函数

### 10.5 两条不显然的口径（写错任何一条，规则一上来就误报或说谎）

- **`server` 锚定是必要的**：同文件里的端口探测写的是 `probe.Get("/")`（那是客户端探测请求，
  不是路由注册）。去掉锚定或改成扫 `\.Get\("` 会把它当路由 = 规则第一天就说谎。
- **生成表驱动的注册循环不会被自己的规则误伤**：它写的是 `server.Get(std::string(route.path), …)`，
  括号后紧跟的是 `std::string(` 而不是字符串字面量。这条边界是"面 2 与消费点共存"的前提，
  改注册写法前先想清楚这一点。
- **注释里的端点名不算**：`"GET /…"` 那条只认双引号紧跟方法名的形态；Doxygen 注释里写
  `GET /state` 用的是反引号。
- **字段字面量只扫读请求体的那几个文件**：`body.at("…")` 这个写法在配置解析等处也可能出现，
  全局扫会误伤。限定名单写在 `rules_rpc._is_rpc_request_file`，口径显式；漏加一个新文件的后果
  是那条面少扫一个文件，而面 3 仍兜着装饰化。

### 10.9 面 5｜response 段自洽（批 3）

`response = { fields = { … } }` 与根级 `shapes` 是**文档面**：C++ 不消费它（回包由处理函数
拼装，没有运行期校验可挂），消费方 = 人工参考 `.md` 与客户端读的 `.json`。没有运行期消费者
⟹ 它的"不变装饰"只能靠 schema 侧的结构规则钉，逐条：

| 判据 | 为什么 |
|---|---|
| 每个端点必须有非空 `response.fields` | 批 3 的交付就是"回包字段进表"；漏一个端点 = 那份文档对它失明 |
| `kind` 在词表内（`config.RPC_RESPONSE_KINDS`） | 词表外的拼写（`uint64`、`int`）会原样进 md，客户端按它写解析代码 |
| `object` / `object[]` 必带 `shape` 且指向存在的 shapes 条目；非 object 不许带 | 子结构字段清单没地方登记 / 引用悬空 = md 渲染出断链 |
| `optional = true` 必带非空 `absentWhen` | 对客户端来说「能缺哪些」与「有哪些」是同一份契约的两半，只登记前者等于没登记 |
| 端点内响应字段名唯一；shapes 条目名唯一、fields 非空 | 重名 = 后一条永远读不到（面 3 同款失效形态的响应版） |
| 每条 shape 至少被一个端点或结构引用 | 没人引用的结构 = 装饰（§3.3「没有消费点的字段不进 schema」的 shapes 版） |

词表与请求侧的 `RpcFieldKind` **刻意不共用**：响应没有运行期判据本体，那份枚举是校验档位，
这份是文档口径，硬合并会让"加个文档类型"变成"改校验器"。

### 13.2 设计红线（为什么是静态调用点口径，不是运行期计数——挂号原文的理由，别翻案）

> 别选「运行期计数 vs 写死常量」那条看着最省的设计——运行期计数把循环内断言按**执行次数**计，
> 而循环上界一旦随数据变（表长、机位数），护栏就在**合法改动**下变红；静态调用点口径虽然土，
> 但它**与激励无关**。（→ `docs/mdi_plan.md` §11.5 / 总账 债-123）

所以三口径全是**文本口径**：① 就是挂号口径命令的 `grep -cE` 行数语义（连它「一行两条只数 1」
的钝处都保留——那个形态由 ① ≠ ② 的分叉报出来，而不是偷偷修正）；② 剥注释数出现次数，与 ①
配对才能区分「死断言」与「一行两条」；③ 是人申报的期望值。运行期一个数都不采。

## 16. 对话黑话冻结：方言增长棘轮 + 对照表死词 `jargon_ratchet_checks`

### 16.1 立论：文档是这套方言的**生成器**，不是受害者

用户反馈"和 LLM 交流很累"，点名 门 / 射程 / 装饰 / 靶。实测把成因定位到两处，都不是"模型爱装"：

1. **镜像效应**：AGENTS.md（218 行）+ 5 个 skills（540 行）每次开工都进上下文，模型照那个文体
   回话。而这套词不只在 docs——`rgl/` 与 `tools/` 的源码注释里 判据 1713 次、门 1438 次、
   锚点 583 次。**改模型没用，要改它每次必读的那一层。**
2. **激励正好在造词**：AGENTS 的预算制（"写结论 + 指针不写论证"、"AGENTS 是预算制不是垃圾桶"）
   让一个**已付过钱的隐喻**（"不在射程内"）比一句白话（"这个检查只扫 `.cppm`，所以 `.lua` 里的
   改动它看不到"）便宜得多。于是写文档省下的力气，全部转成用户**每一次对话**的解码成本——
   **而没有任何规则给这笔账定价**。本条就是把这笔账的**增量**挂回写文档的人身上。

### 16.2 判定（warning 级，两条）

- **① 棘轮**：对照表里处置为「换掉」的词（纯隐喻、无代码 / 命令 / 配置锚点，删掉不丢信息）在
  某文件的出现次数 **> 基线** → 点名。存量钉死**只准降不准升**，所以今天不必清洗那 750 处，
  但谁也别再加。收账 = `--update-jargon-baseline`，形态同 §1.7 / §12（含"扫描面没跑起来就
  **拒绝落笔**"那道闸）。
- **② 死词**：对照表登记了、扫描面里却 0 次 → 点名。表里留一条没人用的词 = 下一个会话照旧拿它
  当权威解释，而它解释的东西可能已经不存在（同 §1.9「副本必然漂」）。

**扫描面 = 驱动对话文体的那一层**（`AGENTS.md` + `docs/**.md` + `.opencode/skills/**/SKILL.md`）。
**排除两份"以这套词为对象"的文档**：对照表本体与本文——它们必须把词点出来才能翻译 / 治理它们
（不排除的话它们自己就是最大的"违规"文件）。**边界**：只有对象是这套词本身的文档可进排除名单，
写正文时想用某个词就改用白话，不是往名单里加文件。
**不含源码注释**：那边单条有局部上下文、读得懂，一次性清洗是纯 churn，且对话文体不由它决定，
钉那里命中不了成因。

### 16.3 名单不抄进 config（本规则与 §反模式唯一的结构性分歧）

术语名单与"哪些词该换掉"的**唯一真相源 = skill `rgl-glossary` 的 markdown 表格本身**
（第一列 = 术语，` / ` 分隔同义；第三列 = 处置 ∈ `config.JARGON_DISPOSITIONS`）。
config 只拿判据参数（扫描面、基线路径、处置词表）。

理由：把 22 个词抄进 config 再写一条规则去对账两份副本，**正是本项目反复红过的「抄名单」形态**
（`rgl-doc-placement` §反模式）。对账两份副本严格劣于只有一份。

### 16.4 失效出声（error 级）与阳性锚点

| 变异 | 期望 | 实测 |
|---|---|---|
| 往扫描面某文件加一句含「射程 / 红线」的新话 | 该文件两词各点名一次（`0 → 1` / `3 → 4`） | ✅ |
| 表里某行的处置写成词表外的值（如「待定」） | ERROR「无法执行」——处置写错 = 棘轮面静默变化 | ✅ |
| `## 对照表` 小节改名 | ERROR「找不到小节」——改名会让规则静默变瞎 | ✅ |
| 表里加一条全仓没人用的词 | warning「扫描面 0 次」 | ✅ |
| 基线文件坏成 `{"nope": 1}` | ERROR「基线不可用」——此时「零警告」不代表没新增 | ✅ |
| 全部还原 | **0 条** | ✅ |

本规则的判定是**数数**，所以"没数"必须区别于"零新增"：名单空了不会少一条警告，而是整条规则
静默变瞎，而"零警告"会被读成"方言没再长大"（同 §1.6 / §10 / §14 的取向）。

### 16.5 盲区（写下来不装没看见）

- **管不到对话**：回复不是仓库文件，写不出断言。对话语域那条住全局
  `~/.config/opencode/AGENTS.md`，**是注释不是防线**，会随时间失效——本条只保证方言不再长大，
  不保证模型每次都说人话。这是本项目"写不出机器判据的必须就地承认"的一条。
- **只数「换掉」，不数「保留」**：判据 / 护栏 / 假绿 / 阳性锚点 这些词压缩的是真区别，白话写要
  一整句，刻意不棘轮。表里对它们的要求是"第一次对用户提及时补一句白话"，那半句没有机器判据。
- **子串计数**：`靶` 会吃进 `靶子`、`造靶`（同时计入两条）。棘轮是单调的，重复计数不影响
  "只准降不准升"的语义，故不为此上词边界——中文没有 `\b`。
- **一词两义（`门`）只登记不拦截**：它在项目里既指"配置开关"又指"会卡住构建的检查"，比黑话更
  累人，但机器分不出用的是哪个义项。表里的要求是用之前点明。
