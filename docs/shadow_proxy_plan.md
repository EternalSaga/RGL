# 阴影投射代理层（shadow proxy）

> **状态**：现行（2026-10-20 立，同日改形态：算的位置从离线挪到启动期）。shadow proxy 这条线的
> 批次拆分与定案结论写在本文件。机制深版仍以各 `.cppm` 文件头注释为权威；阴影路线收敛（配置面 /
> 四条软影路线 / IZB 交付关闭）→ `shadow_routes_plan.md`；成本读数 → `还债实测数据.md` §2.2 §4 与
> `mdi_plan.md` §18/§19。**本文件不抄截图锚哈希**（逐位基线的现行哈希 → `还债总账.md` 开头那块声明），
> **不抄判据条数**。

## 0. 一句话

阴影投射物今天**没有自己的表示**——它是主 opaque 遍历顺路产出的临时量，选级直接吃主视图的
`shadow_lod`，而一个 primitive（= 一个材质批次）里的所有部件**共享同一张简化层级、在同一级一起
塌**。实测后果：贴在更大主体上的细附属结构（花箱 / 牛腿 / 窗棂）被并进邻近大簇后**不再单独投影**
（四级全走简化时近场 186 个小阴影丢 24 个；出厂档也丢 13 块）。本批在「资产表 + registry」与
「阴影段 draw 清单」之间插一层 **proxy 表**：一份**启动期由纯函数从簇产物算出、逐帧只查询**的阴影
投射物台账，让"投什么影"不再复用"主视图怎么画"的答案。

**GPU 侧零改动**：着色器一行不改、零新 binding、零新 dispatch、零新附件。

## 1. 用户拍板（2026-10-20，七项）

| 项 | 定案 |
|---|---|
| proxy 深度 | **含世界空间组织**（不是只到"分量级表示"） |
| 算在哪 | **启动期算，不改产物格式**（用户追加拍板，推翻本文件初稿的"离线烘焙 + 抬 `kFormatVersion`"）。理由 = 连通分量与合并判据从现有产物段就算得出来（§3.2），付不起改格式的代价；**真嫌启动慢再加烘焙选项**，届时只是把纯函数的输出序列化（§3.3） |
| 债-108 | **从并批里拆出去，另批做**。position-only 顶点池是"省显存"的一份**新数据**，引擎侧现排 = 拿运行时多花显存和一次全池重排去换启动后的省显存，纯亏 |
| 逐位基线 | **按债-86 门分区**：新门默认关，门关态逐位不变是硬护栏；门开态用绝对量判据 + 成本验收，逐位基线不主动重立 |
| 与渲染图 | **图侧零改动**——proxy 不产生 pass、不产生图外工作项（§3.5） |
| MDI | **兼容性是硬性约束，不是注意事项**（§3.6 R2/R4）；阴影段真 MDI 实测净亏 +0.35ms（`mdi_plan.md` §19.18/§19.20），proxy 不得往那个方向再加压力 |
| 库形态 | 计算模块进 **`rlbase`**（`rgl/CMakeLists.txt` 里它本就是 `add_library(rlbase STATIC …)`，被上层逐层链接）⟹ **不新建 CMake target**。三条附带收益：整层无设备依赖 ⟹ `just test` 毫秒级可钉；configure 期归属完整性闸门自动核对登记；`rules_layers` 扫 import 边，逆向依赖当场链接失败 |

> 立项过程中被实测推翻的一条论证（本会话自己犯的，写下来防重犯）：**"交付路径 GPU-bound ⟹ 不该把
> 计算放 GPU"是反的**——GPU-bound 恰恰意味着"少量 GPU 计算换大量光栅"是正收益。而 `mdi_plan.md`
> §7.4 那条"簇粒度剔除对阴影段可证上界只有 0.31ms"否的是**剔除粒度**，与**选级**计算放哪无关，
> 拿它反对 proxy 的 GPU 化属于错置。真正决定"预计算 vs 运行期算"的不是性能取向，是 §3.2 那条闭式：
> **proxy 的选级决策本来就只依赖一个离散量**。

## 2. 病灶：一个 primitive 共享一张 DAG

### 2.1 当前数据流（proxy 的插入位置 = ② 那一行）

```
① 离线  tools/meshlet_pack：逐 glb primitive（= 逐材质批次）跑 clodBuild
        → VertexPool 48B / Clusters(DiskCluster.error 逐簇) / Tris(8bit 局部索引)
          / Remap(逐簇 全局顶点下标) / Groups(depth) / Nodes
② 每帧  rgl/render_list_impl.cppm  主 opaque 遍历的同一个 each 循环内顺路：
          collectShadowCasters(asset, mat, 世界球, objectSlot, lodTable)
            → ShadowCandidate{ 世界球, objectSlot, 三个 pipeline 索引, 簇区间 }
        ↓ buildShadowVolumes → 逐级 casterInShadowVolume → emitShadowCasters
          → std::array<std::vector<DrawCall>, kActiveShadowCascades>（段名 shadow0..3）
③ 图内  decorateShadowPass：图首插 4 个 depth-only pass，各画图集一块 tile，loadOp=clear
④ 下游  csm/pcss/evssm 采样（shadow.slang）· evssm_moments.compute · izb_create.compute
```

**④ 全是图集的下游，没有一条路线自己收集投射物** ⟹ proxy 只有一个出口要服务（② 的产物）。
这是它边界干净的全部理由。而 proxy 表插在 ② 的**上游**、图编译之后、录制之前的 CPU 相位。

### 2.2 病灶的机制（一句话，别再重查）

`MeshletShadowLodTable::Entry` 是**每 objectSlot 一个 `(start, count)`**——一个 prim 的选中级是
**单一整级**，而该 prim 里"大墙面"与"挂在它上面的花箱"同材质 ⟹ 同 prim ⟹ 同一张 DAG ⟹ 选到粗级时
花箱的簇已被 `clodBuild` 合并进墙面的簇，**它作为独立遮挡体已经不存在了**。

同一条"分区粒度"在成本侧的镜像就是 `mdi_plan.md` §7.4 那条负知识：group 误差取分区内**最大值**
（簇误差长尾：depth4 p50 2.4cm / p90 18cm / max 1.6m）⟹ 按纹素预算 cut 会**整组退化到 L0**。
**画质面丢影与成本面拿不到收益，是同一个病的两面。**

### 2.3 已钉死的事实（指针表，读数去出处看）

| 事实 | 出处 |

## 3. 设计定案

### 3.1 三层形状

**第 1 层 `shadow_proxy_types`（rlbase，纯 CPU，进 `just test`）**

```
ShadowProxyItem {
    StableId      id;            // 稳定身份（不是 objectSlot 下标——ECS 规范 5）
    uint32_t      sourceAsset;   // 指回资产，不引侧数组下标
    uint32_t      component;     // 连通分量号：一个 primitive 内的空间独立部件
    Bounds        localBounds;   // 分量自己的包围（不是整 prim 的）
    ShadowRepr    repr;          // ← 变体，见下；本层唯一的"让错的东西编不过"
    CasterFlags   flags;         // alphaBlend 排除 / doubleSided / mask
    bool          finePart;      // 是否"贴在大主体上的细附属结构"
}
ShadowRepr = variant<LegacyMeshRanges, ClusterRange{base,start,count,level}, ProxyVolume>
```

变体化的全部理由：今天"阴影用主视图的 D"是一个**隐式默认**，写不出"我没考虑过这件事"；变体后必须
显式选一条。`ProxyVolume` 这一档**本批不实现**（§5），但**类型先占位**——占位不占代码，缺了它将来
加档要改所有 `visit`。

**第 2 层 选级（纯函数，proxy 的智力内容）**

```
selectProxyRepr(item, level) -> ShadowRepr      // level = 量化档号，不是相机距离
```

判据从"主视图屏幕误差"换成**光空间纹素尺度**：分量的最小遮挡特征 < N × 该档本级纹素 ⟹ 禁止使用会
把它合并掉的层级。闭式、可单测、有反向用例（R2）。

**第 3 层 建表（启动期纯函数）与消费（装配层）**

- **建表 = 一个纯函数**：输入 = 簇产物的只读视图（`MeshletAsset` + `MeshletRangeScan`，与
  `scanMeshletLod` 吃**同一对**入参），输出 = proxy 表。🔴 **不碰设备、不碰单例、不读配置**——这条
  边界是 §3.3 那条"将来加烘焙"的全部前提，也是它能进 rlbase、进 `just test` 的原因。
- 消费：`collectShadowCasters` 从主 opaque 循环里**搬出去**，改成独立一趟；`emitShadowCasters`
  只吃 proxy 条目。
- 剔除：条目带自己的包围球 ⟹ 剔除粒度从 prim 降到分量。
- 门关 = **连表都不建**（先例 = `wireMeshletBindings` 首行 `if (!meshletAssets) return std::nullopt;`）。

### 3.2 承重判断：选级只依赖一个离散量（本批最重要的一条）

选级依赖的相机量只有级联纹素尺寸 `texel_c = 2·r_c / tile`，而 `r_c` 只经 `quantizeShadowDistance`
依赖**量化后的 far**，那个量化**取 2 的幂**（债-139，2026-10-19 改）。far 在 [0.5, 64] 之间 ⟹
**全部合法取值只有 8 个档**。

⟹ proxy 表按 **`(分量, 量化档) → 选级结果`** 组织，运行期只做"查档 + 查表"。五条后果：

1. **MDI 契约一字不动**：CPU 仍然完全知道本帧每条目画几簇 ⟹ `MdiShadowRow` 里**三枚由选级派生**的
   字段全部闭式同源：word[0] `groupCountX`（本行 task 数）、word[4] `clusterStart`、word[5]
   `meshGroupCount` = `meshletTaskCount(选级后簇数)`。（`rowBase` **不在行表里**，它由
   `MdiShadowRowLocation` 进 12B push，与选级无关。）
   🔴 **反过来，一旦选级改成 GPU 现算，CPU 就写不出 task 数**，只能取 L0 上界再靠 `gcX=0 ⟹ 零 task`
   剔 ⟹ ★M-3T-c 刚拿到的"每级联 task 数 4724 → 1530（3.03×）"当场回吐。这就是 §5 把逐簇 cut 单独
   隔离出去的全部理由。
2. **顺带结掉债-107**（`shadow_lod` 全局单值、`Entry` 无级联维度）：表的第二维**就是**档，逐级分立
   从"要给 Entry 加维度、表体积 ×3"变成"表本来就有这一维"。
3. **跨档跳变变成可枚举量**：8 个档的选级结果全都能打日志，"每跨一档固定付出 0.32–0.40% 像素阴影
   状态翻转"那条实测从此有常驻机器版（先例 = `meshlet_lod` 的 `costTable` 把一次性读数变启动日志）。
4. **它同时解释了"为什么可以启动期算"**：要算的是 `条目 × 8` 个选级结论，不是逐帧逐相机重算。
5. 表体积 = 条目数 × 8 × 数字节。**P0 要量的第三个数就是它**。

### 3.3 「先启动期算，将来再烘焙」为什么不是临时方案

因为**接缝已经在那儿了**：§3.1 第 3 层那个纯函数的签名就是 `(产物视图) → 表`。加烘焙 = 把它的输出
序列化进一个带缓存键的文件，读取侧优先命中缓存、未命中就现算——**表结构与判据一行不改**。反过来，
若一开始让建表过程碰设备句柄或读配置单例，将来加烘焙就得先重写一遍。所以这条不是"以后再说"，是
**现在这一批就把边界钉住**（判据 = R7）。

缓存键照 `meshlet_pack` 的现成口径：`sourceSha1`（输入 glb 全文件 SHA1）+ `configFingerprint`
（判据配置字段的 FNV-1a）+ `toolVersion`。⚠ 三者缺一就会命中过期缓存——那是本项目反复红过的
"看起来已完工的半吊子"形态。

### 3.4 世界空间组织 = 光空间固定基网格（sun-grid）

条目按**光空间固定基** `(s, u, d)` 的均匀网格登记，格距 = 该档本级纹素的**整数倍**。

为什么是这一组轴，而不是世界 AABB 网格或 clipmap：`buildShadowVolume` 的 texel 吸附**已经**用这组
轴做世界锚定了（5a-8b 定案：三轴只依赖太阳方向，恒定；三坐标各 round 到 `2r/mapSize` 格点）。
proxy 网格与它同轴 ⟹ 两条性质白拿：

- **格点世界锚定**，相机不动它（与已结案的"转视角影子游动"同一套坐标系，不新造第二个原点）；
- **格距与纹素整数倍** ⟹ "页 → tile" 的**位置**偏移是整数纹素（这是将来时序摊销唯一可行的前提：
  内容相同 + 整数偏移才谈得上复用，见 §5）。

不选 clipmap / 八叉树的理由：它与"4 级级联 + 2 的幂量化"是**同一件事的第二套实现**，而本仓的级联
口径已经由 `quantizeShadowDistance` / `cascadeSplitDistance` / `computeCascadeSpheres` 三处单一来源
管着——再造一套层级 = 造第二个会漂的真相（AGENTS 哲学第 1 条）。

**顺带收益（不是目标）**：条目登记世界锚定后，"哪些条目进哪一级"不再随相机连续漂。今天它是
实测随相机变的（两机位逐级投影体数 514/1459/1497/1511 vs 483/1477/1507/1517）。**但别把它读成
债-139 修好了**——级联盒本身仍随相机走，跨级缝 0.73 纹素原样在。

### 3.5 与渲染图的关系：图侧零改动

| 问题 | 答案 |
|---|---|
| 落在图外？ | **否**。图外工作项的语义是"自己录命令、自己发 barrier、向图申报位置契约"（`RgOffGraphWorkDecl`，现有四家 = meshlet_cull / IZB / EVSSM / FSR）。proxy 一条命令都不录。 |
| 以可选原语加入图内？ | **否**。proxy 不写附件、不产生 GPU 资源、没有布局要转 ⟹ 做成 pass 是范畴错误，而且会给债-16②（两套执行世界观）添第三个世界。 |
| 那它在哪？ | `renderListSystem` 里今天 `collectShadowCasters` 那一行的**上游**——图编译之后、录制之前的 CPU 生产者相位。产物类型与今天完全相同（`array<vector<DrawCall>, kActiveShadowCascades>`）。 |
| 进 mesh shader 吗？ | **不进**。mesh shader 读的还是原簇产物，身份与簇区间从 push / MDI 行表来。proxy 需要进 shader 的那一天 = §5 的逐簇 DAG cut（一条 draw 内不同簇取不同级，那时才要一张级号位图），而那一批与 MDI task 数有真冲突。 |
| 图侧真改动是什么？ | **只有时序摊销会动图**：每级 pass 现在恒 `loadOp = clear`（注释里记着 2026-09-29"只清级 0 → 块 1..N 永不初始化 → 全判影加深 60%"那个坑），而"干净 tile 不重画"要求 tile 内容**跨帧活着**，`RgPassDesc` 是启动期编译的。三条候选形态与代价 → §5。**proxy 本体不含它。** |

### 3.6 七条硬性约束（每条标机器判据；写不出判据的当场明写）

- **R1 proxy 表是阴影投射物的唯一来源。** 门开态下阴影段每条 draw 必须能反查到一个 proxy 条目。
  判据 = 帧末对账计数（`draw.count` 侧新增一项，形态照 `mdi.tasks` 的先例：构建侧入账，
  🔴 **不从执行器读**，不把行表语义漏进盲执行器）+ 门关态 `collectShadowCasters` 原路径保留。
- **R2 选级决策只依赖量化档号，不依赖任何连续相机量。** 判据 = `just test` 单测：给连续变化的 far，
  选级结果**只在 2 的幂档边界变、档内恒定**；反向用例 = 故意让选级读未量化的 far，档内必须出现变化
  （否则这条断言是恒真的假绿）。**这条是 MDI 兼容性的承重墙**，也是 §3.2 那条闭式的机器化。
- **R3 门关逐位不变**（债-86 门分区）。判据 = `just regress ab` 对逐位基线（台账里编号 A 那张，
  哈希 → `还债总账.md` 开头那块声明）。⚠ 门关态 ≠ 出厂默认态那条口径照旧适用。
- **R4 proxy 不得增加阴影段 draw 数。** 判据 = 门开/门关两态同机位 draws 比 ≤ 1.0（常驻计数器，
  不是人工看图）。立论 = 阴影段真 MDI 实测**净亏 +0.35ms** ⟹ 该段对命令组织开销敏感到这个程度。
  分量拆条数若涨，必须靠"同 prim 的分量能合并成一条 draw 就合并"抵掉；抵不掉 = 设计错，不是代价。
- **R5 分量划分互不相交、并集 = 该 prim 全部三角。** 判据 = 建表纯函数内的 invariant（照
  `meshlet_lod` 五条不变量的形：每条一个**两两不同**的错误串、前缀点名，是"产物或判据漂了"的
  探测器）+ 启动日志读数。**因为算在启动期而不是离线，这条从"审一次产物"升级成"每次启动都验"**
  ——这是本批用启动时间换来的东西，值。
- **R6 proxy 不改产物格式、不抬 `kFormatVersion`。** 判据 = 产物文件的 SHA 基准与 `format.h` 的
  段表**零改动**（构建闸门本就盯产物）。若将来加烘焙，写的是**旁路缓存文件**，不是往产物里加段
  （§3.3）——两条的失效形态不同：加段错了 = 全场景几何画错，旁路错了 = 顶多算一遍。
- **R7 建表是纯函数：入参只有产物只读视图，不碰设备、不碰单例、不读配置。** 判据 = **归属即判据**：
  模块登记进 `RGL_BASE_MODULE_SOURCES`（rlbase = 整层无设备依赖），`rules_layers` 逆向 import 当场
  链接失败；再加一条 `just test` 用例直接栈上构造入参调用它（能调通 = 边界成立）。

## 5. 明确不做 / 触发条件（防止反复重提）

| 项 | 处置与理由 |
|---|---|
| **离线烘焙 proxy 表** | **本批不做**（用户拍板：先启动期算）。**触发条件** = P1 打进启动日志的"建表耗时"读数超标（超标线由 P0 的第 4 个数定，不拍脑袋）。**做的时候** = 旁路缓存文件 + 三件套缓存键，判据与表结构不改（§3.3）。 |
| **分量级簇序重排**（让花箱走 L0、墙面走 L5 且同一条 draw 内） | **不做**。它**必须**离线（同分量的簇在产物里是散布的，连续化只能打包时重排），且会牵动 L0 口径（`refined == -1`）、`meshlet_ranges` 的 base、`meshlet_lod` invariant 2/3、全部 SHA 基准。**触发条件** = P2 落地后近场存活率仍 < 1.000 而 prim 级保守已到极限。 |
| **逐簇 DAG cut**（`mdi_plan.md` §7.4"仍然要做"清单第三条） | **不做进本线**，独立裁决。它与 MDI 有**真冲突**（§3.2 后果 1：GPU 现算 ⟹ CPU 写不出 task 数 ⟹ ★M-3T-c 的 3.03× 收敛回吐）。**触发条件** = 上面那条也救不回来时。**仍然要做**：这条本身没错，§7.4 的作用域写清了（只否"拿现成 group 级 cut 直接换收益"）。 |
| **时序摊销**（债-82，阴影段零脏标记 / 零隔帧） | **不在 proxy 本体**。proxy 只是让它**可表达**（条目有身份才谈得上"脏"）。真做要动图：① 逐帧 loadOp（clear↔load）= 给图新增一条逐帧轴，barrier 与对账全跟；② 每级独立附件 + 逐帧选插图 = 撞"图形态启动期定"，要 `dynamic_render_graph` 承接；③ 图集变持久资源 + 显式 blit 复用 = 图集脱离 `render_target_cache` 每帧重建，生命周期改动。三条都得独立设计，**别当顺带活干**。收益口径 = 债-82 剩余面（LOD 已拿掉那 5.45ms 的约 78%，时序摊销与它可叠加）。 |

## 7. P0 要量的四个数（决定 P2 形态，不是走流程）

1. **bistro 1591 个 primitive 里有多少含细附属结构，它们的 L0 三角占全场景比例。** 这个数直接决定
   "prim 级保守"（`effectiveD = min(D, 自身最深级, maxSafeLevel)`，draws 一条不涨）是终局还是过渡。
2. **分量数分布**（每 prim 的连通分量数、每分量的三角数）。决定条目数量级，以及 R4 抵不抵得住。
3. **按 8 档组织的 proxy 表体积**。决定它是"启动期读一张表"还是"要分片"。
4. **建表纯函数的实测耗时**（新增，因为算挪到启动期才需要它）。决定 §5 那条"离线烘焙"的触发线。

**四个数都能从产物本体算出来，不需要引擎、不需要 GPU**：`DiskPrim` 给 prim 边界，`Remap` + `Tris`
拼出全局三角连接性（并查集的输入），`DiskCluster.error` / `Groups.depth` 给逐级误差与层级。
——这是把 P0 排第一位的全部理由：它便宜，而它决定后面三批的形状。

**耗时的那个粗估**（P0 要把它换成实测）：L0 = 27,487 簇 / 2,832,120 三角 ⟹ 约 5.7M 次 union；
再遍历全 12 级 61,518 簇判合并 ≈ 7.8M 三角。单线程 **~100ms 量级**，相对 boot 2.8s（其中 2.0s 是
一张 env 贴图上传）约 3.5%，且门关时根本不跑。⚠ 这是**按产物计数推的，不是实测**——写进 P1 的
启动日志读数后才算数（先例教训：债-102 那条"量债的脚本没入库"）。
