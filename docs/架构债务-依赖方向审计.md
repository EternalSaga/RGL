## 债务 1（扎眼）：`vk_resources -> cube` —— 内容模块住进了资源内核

**证据**（符号级，不写行号）：

- `vkresources.cppm` 接口 `import cube;`
- `vkresources_impl.cppm`：**`Resources` 构造成员初始化列表**直接
  `vertexBuffer(createGpuBuffer(RGL::cubeVertices...))`、`indexBuffer(createGpuBuffer(RGL::cubeIndices...))`
- 同文件 `writeDescriptors()` 把 cube buffer 地址写入 heap slot 0/1，注释自曝：
  *"构造体内调用（**cube buffer 移入资产表前**）：直接用成员取成员地址"*——作者本人盖章的临时态。
- 契约锚：`types_schema.lua` 的 `HeapSlotVertexOffset=0 / HeapSlotIndexOffset=1`（"cube 顶点 0 / 索引 1 之后"
  的分配约定），model 管线 `heapSlotOffset=2` 以 cube 占位为前提；`main` 的 "[2,2+N) 顶点槽" 容量契约、
  纹理首槽=白纹理的断言，同一族语义。
- 对照面：**gltf 路径的依赖方向是对的**（`model_importer -> vk_resources`，内容在上消费内核），
  唯独 cube 反向被内核持有。cube 不是和 gltf_loader"平起平坐"，是被塞进了地板下面。

**为什么是债**：内核（descriptor heap 分配、staging、RT 管理）与一份演示几何体焊死；
删 cube / 换 cube / 加第二种程序化几何，都要动 `Resources` 构造与 slot 契约。

**两条修法**（二选一，都可行）：

- **A 删除**：场景已全模型化（bistro），`showCube` 本标注"Phase 1 遗留；模型在场时通常关掉"。
  删 cube 模块 + `scene_config.showCube` / `entities.type="cube"` + cube 管线注册，
  slot 契约整体前移（model 顶点基址 2→0）。最干净，但失去"零资产可跑"的排障场景。
- **B 并列（推荐）**：cube 升格为**虚拟几何资产**——与 gltf 走同一条注册路
  （`model_importer`/`asset_table` 增加 `builtin://cube` 之类的内建源，产出的上传/注册/矩阵槽语义
  与模型实体完全同构）。`Resources` 不再认识 cube，只认识"资产表驱动的 slot 分配"。
  scene.lua 的 `entities={type="cube"}` 行为不变，用户无感。

**连带清单**（无论 A/B 都要碰）：`types_schema.lua` + `types_generated` 的两个 slot 常量语义、
`vkresources.cppm allocSlot` 基址约定、`main` 容量契约断言文案、`scene_config` 的 `showCube`/cube 兼容合成、
cube mesh 管线注册（shader_registry）、默认 `render_graph` 三段图的 opaque 段 drawSource 名。

## 债务 2（隐蔽）：`render_list -> scene` —— 机制层回头吃策略层

**证据**：

- `render_list.cppm` **接口级** `import scene;`，消费 `ViewProjection`（DrawArgs 组装的输入）。
- `render_list_impl.cppm` 进一步消费 `SceneSpin`、`Camera`。

**根因诊断**：不是 render_list 要背锅，是 **`scene.cppm` grab-bag 化**——一个模块里同时装着
上下文值类型（`SceneBounds` / `SceneSpin` / `ViewProjection`）与每帧 system（spin/projection/…）。
`scene_config` 也不得不 `import scene`。值类型被 system 连坐。

**修法**：把 `SceneBounds / SceneSpin / ViewProjection`（以及跨层引用的其它纯值类型）
抽成叶子契约模块（如 `scene_context`，只 `import rlstd` + camera 值类型），
`scene`（systems）、`render_list`、`scene_config` 都改指它。原 `scene` re-export 保持兼容，
逐文件切换。这比"render_list 别用 scene"更符合真实依赖：值类型本来就该人见人用。

## 债务 3（深水）：`vk_resources` 三重职责 = 怪物依赖的本体

入度 8（frame_draw_list / gpu_canary / model_importer / render_list / shader_registry /
texture_pool / texture_upload / vk_renderer）、出度 13，26 字段 / 31 方法。它同时是：

1. **设备级资源管理**：VMA allocator、depth image、descriptor/sampler heap 保留段与 `allocSlot`；
2. **场景级 staging 契约**：`ensureSceneData` / scene data 字节布局（@0 光照头 / @128 矩阵表——
   scene.slang 注释指认的"真相源"）；
3. **内容常量约定**：cube 顶点缓冲、白纹理、env 纹理等具体内容的创建与占位。

债务 1 就是角色 3 漏进内核的通道。**建议缓行拆**（大手术、牵每个消费方），但立一条规矩：
**修债务 1 时不得给它添第四种角色**；将来拆的刀法预告——`heap_allocator`（角色 1）/
`scene_data`（角色 2，与 scene.slang 契约同族）/ 内容注册归还资产表（角色 3 归零）。

## 修复记录（2026-09-08）

### 债务 1 · 方案 B（cube 升格内建几何资产）

新增 `rgl/builtin_geometry.cppm` + `builtin_geometry_impl.cppm`（接口 = 两个声明，实现 = 叶子单元）：

- `uploadBuiltinCube(vkDevice, res)`：cube 顶点/索引 buffer（BDA storage，创建期 mapped 写满）
  + 两个 **几何 heap 槽**（现走 `SlotSegment::Geometry`，计入 `AssetTable::geometrySlotCount`）+ 描述符写入
  + `addIndexedMesh` → 返回资产 id。buffer 创建/描述符代码从 `Resources` 构造体搬来，非新写
- `registerBuiltinCube(...)`：原 `scene.cppm` 的 `registerCubeEntity` 迁入（scene 不再 import cube）
- main 启动流加 **A0 段**（entities 有 cube → 上传内建 cube，先于全部模型槽）→ C2 段之后
  的独立块（天空盒条目之前）注册 entity + `ShaderRegistry::addCubeEntry(meshAssetId)`
  （原构造期恒建 → 按需建，幂等）

`Resources` 侧删除：`import cube`、`vertexBuffer`/`indexBuffer`/`heapSlotVertex`/`heapSlotIndex`/
`cubeAsset`/`cubeAssetId()`、`writeDescriptors()`、`createGpuBuffer()`、构造体内 cube 槽断言。

**slot 契约改动**（原"cube 占位 0/1 → 模型 base 2"一族语义）：

| 项 | 前 | 后 |
|---|---|---|
| `types_schema.lua` cube vertex/index | `heapSlotOffset` 0/1 + cppName 生成常量 | 运行时槽（只留 binding index + shape 校验） |
| `model_schema.lua` | `HeapSlotModelVertexBase = 2` | `HeapSlotGeometryBase = 0`（几何段起点 = 用户槽区起点） |
| `AssetTable` | `modelSlotCount`（每模型 +1） | `geometrySlotCount`（内建几何 +2、每块 +1）+ `expectedGeometrySlot(reserved)` 统一漂移断言 |
| `createDescriptorHeap` 容量 | `HeapSlotModelVertexBase + kUserSlotMargin` | `kUserSlotMargin` |
| `types_generated` | 2 常量 | 空（模块保留，仍校验 types.slang binding 契约） |

有 cube entity 时槽序与旧布局逐位相同（cube 先传 → 顶点 0 / 索引 1 / 模型从 2 起），
故截图 BIT-IDENTICAL 成立（见下）。

### 债务 2 · scene → scene_context 叶子契约

事实核正：原 `scene.cppm` **不含任何 system**（system 在 ecs.cppm / render_list.cppm），
移出 `registerCubeEntity` 后余下全部为值类型/组件（另有 extractFrustum/sphereInFrustum
两个视锥工具 inline 函数）、无任何 system → 直接改名 `scene_context.cppm`
（不留 re-export 空壳，`scene` 模块消失）。依赖面：只 `import rlstd`。
`render_list` / `render_list_impl` / `scene_config(_impl)` / `model_importer_impl` / `ecs_impl`
/ `main.cpp` 全部改指 `scene_context`。
