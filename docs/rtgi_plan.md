## 0. 先立反面：三条"现在别做"的理由

1. **本机是 GPU-bound 贴地板的**（`docs/mdi_plan.md` §1.3 实测：交付档 frame 10.66ms /
   gpu.frame 10.30ms，CPU 真干 3.70ms，余量 0.36ms）。RTGI 是**加** GPU 负载，没有"顺手做一点"
   的空间——它的开销必须从画质预算里换，而不是从帧时间预算里挤。
2. **阴影线自己还没结案**（债-139 世界空间残差卡在测量地板上）。同一条"间接光遮蔽"的语义，
   阴影线没收口就开 GI，等于在两块没钉死的地基之间浇混凝土。
3. **判据网对"整体变亮"是零覆盖的**（债-141 实测：env faces 回落过曝 6.5 万倍、出厂即全白，
   而 `just smoke` / `just test` / `just regress` 全绿了至少 8 天）。GI 是一个**天然会把画面整体
   提亮**的特性。先补曝光带判据 + 钳位自检，再谈 GI，否则 GI 上线就是债-141 的放大版。🔴 同族还有一条
   已单独立账：**债-145**（env 预滤波的 LOD 标度没有任何判据能抓，而 RTGI 要**减** IBL ⟹ 标度错会
   伪装成 GI 伪影）—— 三条地基判据的完整口径在 §5，别只按本条的两条准备。

这三条不是"做不了"，是"按这个顺序做才不会白做"。

## 1. 为什么是现在谈（地基时间线，全部实测）

不是想法变新了，是**能承载它的 substrate 两个月前才出现**：

| 事实 | 出处 |
|---|---|
| `VK_EXT_descriptor_heap` 在 Mesa 26.1.8 = `DONE (vn)`——**RADV 当时没有实现** | `ab/mesa-2618/src/docs/features.txt:625` |
| 26.2.0（release notes 头部日期 **2026-08-05**）：`VK_EXT_descriptor_heap enabled by default on anv, RADV` | `ab/mesa-2625/src/docs/relnotes/26.2.0.rst:88` |
| 本仓口径：Mesa ≥26.2.3 起 RADV **无条件** advertise，不再需要 `RADV_EXPERIMENTAL` | `Justfile:351` |
| 该扩展 = vk.xml 里 number 136、`ratified`，且 `VK_EXT_descriptor_buffer`（2020）被 `deprecatedby` 指向它 | `/usr/share/vulkan/registry/vk.xml:23780` / `:26957` |

**含义**：RT 与本项目绑定模型之间那条接缝（SBT / BLAS / instance 数组到底走 descriptor heap 还是
经典 descriptor set）在两个月前**根本不存在**。"以前不做"不是保守，是没有地基；同理，**现在做也
等于站在一条默认启用才两个月的驱动路径上**——债-140 已经演示过这条路径上有什么（见 §3.4）。

- **判据传统可用**：闭式解探针（`just analytic`）、区域归因判据（`just imgqa`）、逐位回归与同构建

- **透明段已先收**（2026-10-24，债-134 先决结案 = `just imgqa blend-lit`）。**这不是顺手整理，

  连归因都做不了。

## 3. 三条硬账（开工前各自必须出一个数或一个裁决）

### 3.1 渲染图形态：RT 的 barrier 归谁发

- **事实**：`RgPassKind` 至今只有 `drawMesh` / `blit` / `drawLight`，没有 compute；D1 定案 =
  扩资源词表（buffer 档 + storage 读写）+ **第一版 plan-only，发射权不许交给图**；B3（compute
  pass 进图 / 图代发 barrier）明确不做 → `docs/compute_调研.md` §6 D1、§7、§7.22。
- **后果**：RT 会是又一条图外编舞（`OffGraphWorkTable` + sandwich 钩子 + `offgraph_sync` 边名 +
  L1 应发次数账常开）。这套机制已经能跑，但每加一个图外消费者都要人手工申报一遍依赖，**而申报错了
  没人拦**：
- 🔴 **盲区（实测，不是推测）**：`docs/compute_调研.md` §9 N3——descriptor heap 上的 buffer 访问，
  **syncval 开不开都是 0 条**。而 SBT / BLAS / TLAS 恰恰是大量 buffer 访问。
- **要出的账**：加一个 pass kind 的静默点全量答案 = 10 处 / 5 文件、其中六处原本是静默的（§7.16
  已量）。RT 要不要为它重开 B3？不重开 → 图外编舞 + 一条已知无护栏的风险类；重开 → 先付这 10 处。

### 3.2 显存与表容量：两笔从没合过的账

- 簇产物出厂已 **+175.5MiB**（`docs/mdi_plan.md` §18.11），债-108（12B position-only 池，
  175→71MiB）未做。
- 对象矩阵表上限 4096，bistro 已用 39%（⟹ 最多装两个 bistro），用户已裁"不处理"——但那条裁决的
  口径是"当前场景够用"，RT 的 instance 表会直接顶到它。
- RT 还要：BLAS（bistro 1591 个 primitive、最大一枚 82,015 三角）、TLAS、GI 历史缓冲、去噪中间面。
- **要出的数**：BLAS 总字节、TLAS 更新策略（全量 rebuild / update / compacted）各自的代价、
  1080p 下 GI 历史 + 去噪面的 MiB；然后回答一句人话——**这台 8060S（共享显存）装不装得下**。

### 3.3 同帧还是错帧：这条决定后面所有判据设计

- **事实**：独立 compute 队列本机拿不到（选族规则 ⟹ family 0 坍缩成同一条物理队列），D4 已判
  "无可兑现收益"（`docs/compute_调研.md` §3、§6 D4、§9 N1/N4）。
- **但**：N1 的失效条件②写的是"出现**错帧/异步** compute 消费者"——GI 的时域累积正是教科书式的
  那个消费者。所以 D4 那条判定**在 RTGI 立项的前提下需要重读一遍**，别当默认成立。
- **要拍板**：GI 走**同帧**（简单、直接吃帧时间）还是**错帧 + 低分辨率**（省，但要历史重投影、
  遮挡空洞处理，且必须与 TAA / FSR 的抖动口径对齐——注意 `aa=taa` / `--aa fsr --fsr-temporal`
  两档**不逐位确定**，不能立位比闸门，见 skill `rgl-verify`）。

### 3.4 驱动风险（不是账，是税）

债-140（`docs/债140_跨驱动与上游取证.md`）已定案：gfx1151 上「MDI 间接命令 × mesh 真取数链」
概率性 CP 卡死，上游 bisect 到 cac681c9，**截至本文未修**，引擎靠 `meshlet.mdi_shadow_direct="auto"`
绕。含义有两条：① 任何新增的 GPU 驱动路径都要在这台机器上带 workaround 跑；② RT 的间接派发
（`raygen` 走 indirect / SBT）与 MDI 是**同一类"命令流供给"面**，别假设它干净——复现器
（`tools/debt140_repro/`）的骨架可以直接改造成 RT 版的压力测试。

## 4. 与现有光照项的分工：SSR 的增量、IBL 的能量交接

### 4.1 SSR：先答"GI 的增量是什么"

SSR 已落地（Phase 15，`rgl/shaders/ssr_trace.frag.slang` + `ssr_apply.frag.slang`，合成场景
覆盖率实测 97.2%）。**SSR 已经给了"屏幕内几何的间接光"**，所以 GI 必须回答：多出来的钱买了什么？

| 候选增量 | SSR 能不能给 | 撑不撑得起这条线 |
|---|---|---|
| ① 屏幕外能量（背面、被遮挡的面、天花板） | 结构上给不了（射线在屏幕空间走） | **撑得起**，且这是 GI 唯一不可替代的部分 |
| ② 多次弹射（间接的间接） | 给不了 | 撑得起，但判据最难（闭式要复刻两次积分） |
| ③ 透明 / 玻璃 / 水（SSR 射线穿过去） | 给不了（透明不写深度） | 单独撑不起，是①的附带收益 |

- **裁决点**：先做**单弹射 + 屏幕外能量**，还是直接上 ReSTIR / 路径追踪？前者判据可以闭式，
  后者只剩统计判据（方差、收敛曲线），而统计判据在本项目的传统里是**降级**的。
- ⚠ **别把 GI 做成第二个反射源**：如果只做 ①，那与"把 SSR 的 ray march 换成对三角形求交"是同一
  件事的两种实现，成本必须**对比着算**再选，不是先做了 GI 再解释它和 SSR 的区别。

### 4.2 IBL：能量交接与双计（2026-10-25 补）

**本节存在的理由 = 本文立项时把这件事整个漏了。** 全文 grep `IBL` / `env` / 预滤波，在补本节之前
只命中 §0 第 3 条里那句不相干的债-141。RTGI 一旦开始**替代**某个光照项、而不只是往上**加**，
IBL 的能量账就从"美术取向"变成"判据问题"。

**镜面那一半已经解过，照抄即可。** SSR 用的不是"把 IBL 调小"，而是**减法改正**：`ssr_trace` 输出
`weight·(F·reflected − iblSpec)` 与 `weight`（该文件末行），其中 `iblSpec` 是对 `light.frag`
那一项的**逐式镜像重算**（post-lighting 拿不到原值），而 `pbr.slang::shadeAmbient` **一个字未改**。
premultiplied 让加与减被同一个 `weight` 一起平均，事后不需要重建置信度。**RTGI 的镜面通道沿用
这个形态，不需要新裁决。**

这个形态还有一个当时没写下来的好处，被债-144 反过来验证了：加减两侧读**同一张**预滤波图，所以
IBL 内容本身错了也**不会破平衡** —— 那个漏掉的 4π 让加进去的和减掉的一起糊 1.83 级，SSR 的交接
全程自洽。写成"调 IBL 系数"的话，这种一致性根本不存在。

**没解的是漫反射那一半。** RTGI 的 diffuse 顶的是 `irradianceSH(N)/π · albedo · (1−metallic)`
（`pbr.slang::shadeAmbient` 的 `env.mipRange > 0` 分支）。三个具体的坑：

| 坑 | 为什么"调 IBL"绕不过去 | 要出的账 |
|---|---|---|
| **打空 / 追及距离外** | 光线 miss 或超出 trace distance 必须回落到 SH，回落成 0 = 远处天空那一次弹射整个消失。而"调小 IBL"是全局的，做不出"只在命中处减" | 减法必须乘**与加法同一个 confidence** ⟹ confidence 是 RTGI 的一等输出，不是事后估 |
| **AO 双计** | `ao_apply` 现在是 `hdr.rgb * lerp(1, ao, strength)`，乘在**整张已着色成片**上（直接光与 IBL 一起压）。RTGI 已含遮蔽（打空即被挡），再叠 SSAO = 双计；而若 RTGI 也走改正 pass，AO 还会顺手把 GI 贡献再压一遍 | 这是**"遮蔽归谁"的裁决**，不是能量重标：要么 AO 强度折进 confidence 加权混合，要么 GI 上线时裁掉 AO |
| **透明面要镜像两份** | `shadeAmbient` 有两个消费者：`light.frag`（G-buffer 路）与 `transparent.frag`（per-object 材质路）。减法要在透明面上成立就得**镜像两份、而形态不一样** | 这正是**债-136**「算式同源、形态不同源」的正面遭遇 —— 那边留的"已知不等价"清单是一份清单，不是一道检查 |

**硬约束（带作用域，别读宽）**

> **RTGI 不许改动 `pbr.slang::shadeAmbient` 的任何常数与形态**（`/π`、`env.intensity` 的乘法位置、
> 植被 env 镜面归零、`mipRange = 0` 的常 ambient 回落），也不许给 `irradianceSH` 或预滤波链加
> "为 GI 让路"的补偿系数。

- **作用域**：只管**能量与形态**。RTGI 要新资源（G-buffer 加通道、scene data 加槽、SH 的第二个读取
  点）不在本条限制内 —— 那是接线，不是改账。
- **仍然要做的部分**：AO 归属、miss 回落、透明面镜像，本条**一条都不冻结**；它只规定"用减法形态
  解决，不要用重标 IBL 解决"。
- **为什么写成硬约束而不是建议**：判据网的地基是"门关态逐位不变"（总账锚声明处那三枚截图基线、
  imgqa 的影响域判据、`regress ab` 全都预设它）。IBL 常数一旦被 GI 拽着改，"off" 就变成**另一张图**，
  此后"GI 漏出来了"与"IBL 变了"不可分 —— 那是债-141 那个失效形态的永久版。
- **什么实验会推翻它**：若实测发现**镜像重算无法与原项逐位相等**（例如改正 pass 与主 pass 读到的
  量化输入不同源），减法形态就失去"门关逐位不变"的保证，本条随之作废。届时正确做法是把 ambient 项
  整个搬进改正 pass，**而不是回头调系数**。⚠ 本条目前**未做该实验**，它现在是一个带理由的假设，
  不是已验结论。
- **沉淀地址**：`DOC:`（本条）。**机器判据尚无**；候选 = source_checks 加一条"`shadeAmbient` 函数体
  或 `irradianceSH` 求值端系数发生变化、而同批 RTGI 侧文件也被改 ⟹ 出读数提醒"（与债-136 的候选
  护栏同型，同样**不做 error**：改 IBL 本身合法，只有"为 GI 改"才需要问一句）。

## 5. 判据设计（这条线的成败在这里，不在实现）

三条候选，每条都必须带阳性锚点（"改坏就必须红"，答不出红法的判据不配进门）：

1. **遮挡开关对拍（因果泄漏恒等式）**——最便宜，**先做这条**。把某个遮挡体从 BLAS 里拿掉，
   在"附件说这里没影响"的像素上，两张交付图必须**逐位相同**。它不需要任何闭式、不需要基线图像，
   且顺带证明"该附件是交付差的唯一来源"（skill `rgl-verify` §时域/噪声类判据的设计前置）。
   阳性锚点 = 故意让 GI 读一张别的历史面，本条必须红。
2. **能量守恒闭式**——合成场景（纯平地板 + 已知 albedo + 无自发光 + 静态 + 无阴影），单弹射下
   某点该收到多少间接光是可解析的（面对面 = 已知立体角积分）。这是 `just analytic` 那条"独立第二
   实现"传统的延续，也是唯一能挡住"整体偏亮/偏暗"的判据。
3. **收敛与噪声统计**——若引入随机采样：固定种子（`Lcg`）、"帧数 → 方差"曲线、**且不许给带历史
   的档立位比闸门**。这条只能报告不能裁决（同 `imgqa` 的 advisory 定位）。

**必须先补的地基判据**（第 0 节第 3 条）：

1. **曝光带判据**（交付机位 p50/p95 落区间）+ **钳位自检**（大面积纯白/纯黑 ⟹ 判据作废并出声）。
   这两条本来就是债-141 的修法。
2. **env 预滤波的 LOD 标度判据**（债-145）。理由不是"IBL 那条链该有人管"，而是**它决定 RTGI 出问题
   时能不能被归因**：现在没有任何判据抓得住预滤波的标度错 —— 均匀 env 不动点对 `sum/weight` 这种
   归一化加权平均**在任何 LOD 标度下都恒过**，而 `just analytic` 的探针点是 `metal=0` + `rough=0.90`
   （镜面项趋零，且 0.90 恰落在有效位移为 0 的那一级）⟹ 债-144 那个 4π 落地后三锚 Δ0/Δ1/Δ0 逐位
   不变，**判据在、是绿的、与改动没有因果关系**。IBL 只被"读"的时候，标度错 = 画面略糊没人追；
   **RTGI 一开始减 IBL，标度错就变成减法残差，即一个长得像 GI 伪影的东西，必然被归因到追踪器头上。**
   修法候选（含为什么它能抓而均匀不动点不能）→ 债-145 行。

**GI 开工前这三条都是硬前置。**

## 6. 明确不做 / 暂缓（每条带失效条件）

- **不做 RT 阴影**：CSM 已在那条路上，且阴影线自己还有债-139 未结案。失效条件 = 出现 CSM 结构上
  解决不了的遮挡语义（软阴影精度不算，那是 EVSSM/IZB 那条线）。
- **不做 RT 反射与 SSR 并存**：先答 §4 的分工，再谈共存。失效条件 = §4 拍板"①+② 都做且分工明确"。
- **不引入 `VK_NV_cluster_acceleration_structure` / `VK_EXT_ray_tracing_invocation_reorder` 等**：
  `docs/vulkan_extensions_2025_调研.md` 判"与本项目 mesh+shader-object+descriptor-heap 路线无接缝"。
  ⚠ **该判定的前提是"项目无 RT 路线"**，本文若获批即失效，须重评（尤其 invocation reorder 对
  相机相关着色器的 GI 恰是收益点）。
- **不做 DXR 互操作 / Dozen 方向**：没有需求方。
