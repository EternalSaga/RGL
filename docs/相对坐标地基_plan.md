## 0. 两处必须先纠正的结论

本计划立项时，主 agent 先给过一版口头建议，其中两条是错的。错法与正解都记在这里——

⚠ **A 已拍板要做之后，下面两条的性质变了**：它们不再是「为什么不该做」的论据，而是

两条都已经有机器判据（§3 批 1，已落地）。

### 0.1 纠正一：double 修不了抖动，它和 rebase 是两个问题

> 错法：「先把绝对坐标层换成 double，这一步单独就能做，把未来做 rebase 的最大阻力提前拆掉。」

`ULP(|camera|)` 才是抖动的量级来源，而**主导项是融合矩阵平移列 `c3` 的量级**——double 成形后落库仍是
float32，ULP 一分不少（债-85 ①）。所以：

- **债-84**（MVP 用 double 成形 → float32 落库）= 严格更准的**免费改进**，但**不解决抖动**，
  严重度栏自己写着「现在无精度症状」。
- **债-85**（rebase）= 唯一能治抖动的路子，代价是把阴影稳定性重新押上去（§0.2）。

两条**不许合并成一条推进**。合并的后果是：做完债-84 以为精度问题已解决，于是 rebase 的触发条件
（§5）永远不会响，而真正该做的那件事被一个不相关的改进顶掉了。

### 0.2 纠正二：rebase 的 snap 粒度不是相机精度，是阴影纹素

> 错法：「离散重定位，阈值取 2^12 之类的量级，不触发时逐位不变，所以很安全。」

阈值取**相机精度**是错的。债-85 ② 的原文约束：**snap 粒度必须取「最粗消费者」的纹素尺度**
（= 阴影图集纹素对应的世界步长）。机制：

- 阴影级联 0 现在是**相机无关**拟合球 + `kShadowNearFloor` 固定近平面，`computeCascadeSpheres`
  的注释明写这条是「**姿态无关（不引入游动）**」——它是 5a-8b 为「转视角影子游动」结案时钉下的东西。
- 现有 `quantizeShadowDistance` 量的是**深度界**（`frexp`/`ldexp` 取 2 的幂），**量不到原点**。
  ⟹ 全仓**没有任何一个量**能回答「原点该 snap 到哪」。这就是错法能成立的唯一原因。
- 按相机精度 snap ⟹ 吸附格跟着相机连续滑 ⟹ **等于自己把已结案的「影子随视角游动」重新引回来**。

正解：粒度 = **最粗级联的纹素世界步长** = `max(texelSizes)`。该数组的语义「2·r/块边长，每级各自从
自己的球推」在 `render_list_impl.cppm` 的 `fillShadowData`，契约字段 `ShadowParamsBlock::texelSizes`
在 `rgl/shaders/scene.slang`。r 随级联递增 ⟹ 取最大值即取最粗级，**不要绕回去从 r 重算**
（那会造出第二份副本，AGENTS 哲学第 1 条）。**这个量已经存在，只是没有对外接缝**——批 1b 要做的
就是把它变成一个可测的、rebase 唯一可消费的入口。

## 2. 裁决：做，但做对的那件事

### 2.1 「以后推翻全部」的真实原因不是没做 rebase，是把它做成单例

owner 的理由成立（消费者越多越贵）。但要看清**哪些**未来消费者真的需要它——四个里有两不需要：

| 未来消费者 | 需要相机相对坐标吗 | 它要的原点是谁的 |
|---|---|---|
| **体积光** | **要** | 级联体素每级有自己的 tile 锚点，随相机量化 |
| **物理** | **要，且最麻烦** | 物理引擎（Jolt/PhysX 类）全是 float 世界、要求物体离原点近 ⟹ 它要**自己的**原点，且必须能与渲染原点对齐，否则碰撞体与渲染网格分家 |
| **骨骼动画** | **不要** | 蒙皮在**资产局部空间**做，吃的是骨骼矩阵不是世界坐标，float 完全够，原点搬不搬与它无关 |
| **粒子** | **看它住哪** | 可以住在「粒子模拟自己的相对空间」（UE 的 GPU particles 就是这么做的）——那是**粒子系统自己选原点**，不是引擎替它搬走世界原点 |

⟹ **结论：原点不是「一个值」，而是「每个坐标消费者各自携带的一个参数」。**

如果现在把原点做成引擎级单例（`RenderOrigin` 全局一份），那么物理要自己的原点 ⟹ 改它；
体积光每级 tile 要自己的锚点 ⟹ 改它；粒子模拟空间要自己的原点 ⟹ 改它；阴影 snap 粒度要依赖它
⟹ 还是改它。**每个新系统回来改一次同一个全局 —— 那才是「推翻全部」。**

所以本计划里「现在做、以后不推翻」的那件事，不是「把原点搬到相机」，而是：

> **绝对层（double，唯一真相源）+ 一个唯一的「绝对 → 相对」换算入口 + 原点作为该入口的显式参数。**
> 加新系统 = 新增一个原点声明，**不动别人**。

### 2.2 交付形态：门关逐位不变（这条不是保守，是保住归因能力）

🔴 **债-139 未结案。** 它的最后一行写着：分桶只是被证明的那 0.27pp，**世界空间残差 2.73pp 仍卡在
仪器地板上**（鹅卵石起伏），下一步 = 造零起伏合成平地重做那套对拍。

所以「现在做只是推翻阴影」这句要改成：**现在直接开 rebase，等于给一个正在排查中、且排查仪器
刚被证明有地板的系统，同时加一个新自变量。** 那时若残差从 2.73pp 变成 4pp，**没有任何东西能分清
是 rebase 带来的还是仪器地板**——而债-139 已经记录过一次同类自纠（「跨构建相减无效」那批）。

用项目自己反复用的形态解决：**门关 = 逐位不变**。

- 现在做：绝对层 + 原点参数化 + rebase 实现 + 全部消费者接线，**默认关**。
- 门关态下现有全部截图基线、债-139 的排查现场，**一个 bit 不动**。
- ⟹ 「现在做」的收益（以后不推翻）拿到了，「不毁掉归因能力」也保住了。
- 开关何时打开：债-139 结案后，或 owner 手动拍板。这是**一个配置键**，不是一批工程。

### 2.3 一台仪器，两个用途（这是本计划最省钱的地方）

债-139 自己写的下一步 = 「造一块**零起伏合成平地** + 已知前推量，把比对从『屏幕矩形』升级成
『闭式单应 + 零起伏』」。

而 rebase 的正确性判据恰好是同一件事：**同一场景同一机位，rebase 开 vs 关，阴影稳定性读数应当
一致**（不是逐位——坐标变了浮点路径就变，判据是「差异在闭式精度上界内」）。

⟹ **造一次，两边用。** 而且它顺带把债-139 那个卡住的 2.73pp 残差从「仪器地板」里解放出来。
这比「先结案再动」或「直接动」都划算。

### 批 2 · double 绝对层（类型契约 + 真消费者）

**真消费者 = 相机位置的 dt 累加漂移**（这是**现在就存在**的缺陷，不是为字段找借口）：

`rgl/camera.cppm` 的 `applyMovement` 走 `camera.position += (...) * (fpsSpeed * dt)`——
float32 逐帧累加。同一文件里 `frameDrivenCameraYaw` 与 `scene_context.cppm` 的
`frameDrivenSpinAngle` 已经为**角度**做过改造，理由写得很清楚：「dt 累积随帧时长漂 = 对齐根本不存在」。
**位置这一半没人改**。⟹ 批 2 修它，字段当场有消费者。

改动面（**只改类型与累加，不改任何落库形态**）：

| 层 | 改动 | 落库 |
|---|---|---|
| 相机 | `Camera::position` / `target` 升 `glm::dvec3`；`applyMovement` 累加走 double | `cameraView()` 仍产 float `mat4`（`glm::lookAt` float 版） |
| 配置 | 批 0 收敛后的那份 `readVec3` 返回 double 版；`SceneEntityDesc::position`、`Light::position` 升 double | 烘进 `makeRootTransform` 前收窄 |
| ECS | `Transform` 增 `glm::dmat4 absolute`；`local`/`world` 保留 float 且**由 absolute 单点派生** | 不变 |
| RPC | `rpcVec3` / `rpcCameraJson` 改 double（JSON number 本身是 double，`rpcFieldInRange` 已用 `get<double>()`） | 不变 |

必须遵守的机器约束（**不是建议，是会被点名的**）：

- **R-EC2**：新组件/新字段宿主必须在 `rgl/scene_context.cppm` 有 `export struct`
  （`tools/checks/config.py` 的 `ECS_COMPONENT_MODULE`）。R-EC1 不拦 `glm::dvec3`。

### 批 4 · 消费者逐个接线（每个都留门关/门开双态判据）

一个消费者一批，**不许打包**。清单（按风险降序，先做难的以尽早暴露设计错误）：

| 消费者 | 位置 | 为什么难 |
|---|---|---|
| **TAA 跨帧** | `TaaState::prevViewProj` / `payloadMotion`、`scene.slang` 的 `TaaParamsBlock` | 上一帧的「世界」与这一帧**不是同一个空间** ⟹ 必须把 ΔO 精确编进 motion。静止相机 + 移动原点 = 世界坐标每帧变而画面不变 ⟹ 所有「世界差 = 运动」的判据被骗 |
| **velocity → FSR** | `rgl/velocity_field.cppm`（CPU 镜像，须与 shader 同空间）、`velocity.frag.slang` | 🔴 **velocity 图不吃 `historyValid`**，每帧照算照输出给 FSR ⟹ 重定位当帧不能留假运动，必须精确补偿 |
| **阴影 snap** | `buildShadowVolume` 的世界锚定吸附 | 必须走 `rebaseSnapGranularity`（债-85 ②），锚到绝对层，否则纹素格跟相机滑 = 游动回来 |
| 实例矩阵生产 | `render_list_impl.cppm` 的 `spin.matrix * tf.world` | 世界矩阵唯一生产点，改动本身小 |
| view 矩阵 | `camera.cppm` 的 `cameraView` | 平移分量归属哪一层要定死 |
| near/far 自适应 | `projectionSystem`（用 SceneBounds 到相机距离） | 相机相对自己 = 0，距离要从绝对层取 |
| 头区 `eyePos` / 灯位置 | `fillLightData`、`SceneLight::eyePos`、`GpuLight::position` | 方向量不受影响，位置量要减原点 |
| 剔除 | `extractFrustum` / `cull.comp.slang` | 视锥面从 viewProj 现取，跟着走；`CullEntry` 是 node-local，**不用动** |
| SSR 尺度锚点 | `SceneBounds.radius` | 尺度量，平移无关；**只需确认，预计零改动** |

**每条判据 = 三条，缺一不算接完**（第 ② 条是 2026-10-25 实测逼出来的，原计划只有 ①③）：

| # | 判据 | 它证明什么 | 它**证明不了**什么 |
|---|---|---|---|
| ① | 门关逐位不变（**连跑两次**，见 skill `rgl-verify`） | 没改坏旧行为 | 🔴 **完全证明不了「真接上了」** |
| ② | **注入非零原点，该消费者的图必须变** | 这个消费者真的在吃原点 | 接得对不对（只看动不动） |
| ③ | 门开时该消费者的行为有独立判据（闭式 / 图集级逐位） | 接对了 | —— |

**为什么必须有 ②**（实测，不是推测）：把消费点从 `spin.matrix * toRelative(tf.absolute, origin.position)`
改回 `spin.matrix * tf.world`（即**接了但没接上**），门关态 `origin = 0` ⟹ 两者值**逐位相同**
⟹ 单测全绿、门关锚全绿。⟹ ① 单独用会放行「结构上写了、行为上没接」这种形态，而那正是
AGENTS 哲学点名的「看起来已完工的半吊子」。

**② 现在能不能靠编译器免费拿到？部分能，且边界要说清**：实测把上面那个变异直接编译，
`-Werror,-Wunused-variable` 会拦住（`origin` 没人读了）。**但这条保护只在「该函数里 `origin`
只被这一处消费」时成立** ⟹ 批 4 一旦出现一个函数里多个消费者共用 `origin`（例如同时算
`modelMatrix` 与 `eyePos`），摘掉其中一处就不再 unused。
⟹ **单消费者期免费，多消费者期必须手工跑 ②。**

**② 的操作形态**（本批已验证可行）：临时把 `originSystem` 的门开分支从 `throw` 改成写一个非零
`origin.position`，配 `--set 'runtime:coordinate.rebase=true'` 出图，与门关锚比对，**必须不同**；
再注入**第二个不同方向**的原点，两张图**必须互不相同**（否则某分量根本没进链路而没人出声）。
实验完 `cp` 还原（不用 `mv`），并**连跑两次**确认锚复现。

🔴 **注入量必须有区分力，否则 ② 自己先失效**（2026-10-25 实测踩到）：最初按 `100` 注入，
`(100,0,0)` 与 `(0,0,100)` 两张图**逐字节相同**——不是 bug，是交付场景（bistro `scale=0.01`）
被平移 100 后**整个移出视野**，两个方向都退化成同一张纯天空图。
⟹ 只注入一个原点会读出「图变了 ✓」而**实际毫无区分力**（任何超过该阈值的平移都给同一张图）。
正解 = 注入量取**场景尺度的小比例**（本批实测 `(3,0,0)` vs `(0,0,3)` vs 门关，三者两两不同）。
⟹ 「两个原点必须互不相同」这半条不是冗余：**它抓到的第一个东西就是判据自己的失效。**

### 批 4 第三刀的两条收尾裁决（worker 提出，主 agent 拍板）

跳变恒为 0（判据全绿），图却直接没有影子。

⟹ **凡用差分 / 不变量当判据，必须配一条绝对断言**（这里 = 「盒心离球心 ≤ 半纹素」，
即「盒必须装得下级联视锥」）。只问「它动多少」的判据，永远抓不到「它压根站错了地方」。

#### 🔴 批 5 第 0 刀（2026-10-25）：**量具先行**测出「门开会让阴影变差」，批 5 形态因此改变

**机制**（`buildShadowVolume` 的 5a-8b 吸附吃的是**相对**切片球心）：记 `D = dot(ΔO, a)`、

#### ✅ 批 5 第 8 刀（2026-10-26）：`material-swim` 补连续量——「旧绿新红」立住，而主 agent 的独立变异把旧判据钉得更死

## 5. 开关何时打开（原「什么时候才准开 A」，已被 owner 拍板改写）

**本节否的东西已经不被否了**：A 要做（§2.4）。仍然有效的是一条**更窄**的断言——

> 「**在债-139 结案之前打开 rebase 开关**」是不该做的，因为它会让那笔未结的 2.73pp 残差
> 变成无法归因的量。这条否的是**开开关的时机**，不是**做 rebase 本身**。

**批 2-4 不受此限**：门关交付 ⟹ 施工期间开关一直是关的 ⟹ 逐位不变 ⟹ 债-139 的排查现场不受影响。

**什么读数出现时才准打开开关**（三条 AND，缺一不许开）：

1. 批 5 的零起伏平地仪器落地，且 **rebase 开 vs 关** 在其上的阴影稳定性读数差异落在闭式精度上界内。
2. 债-139 结案（那 2.73pp 残差定死是阴影变的还是比对方法本身的误差）——**否则第 1 条测不出可信结果**。
3. 门关态下全量基线逐位不变（这条是施工期持续判据，不是开关判据，列在此处防"边施工边开"）。

**什么会推翻上面这套顺序**：如果阴影换成不依赖世界锚定纹素吸附的方案（§0.2 的前提消失），
则第 1、2 条同时失效，开关可以随批 4 立即打开。**粒度约束（债-85 ②）本身不随之失效**——
只要还有任何消费者在世界空间做格点对齐，它就得取那个消费者的粒度。

**为什么 headroom 测试仍然要留**：它现在不是「准不准开工」的闸门（已拍板），而是
**「门关态下当前机位离触发点多远」的仪表**——开关打开后，它变成「相机离**动态原点**多远」的
持续监控，那才是它长期的用途。

**为什么 headroom 只算距离、不算像素**（2026-10-25 立项当天自我纠正）：本文初稿要求「headroom 把焦距 px
当输入」，这样换分辨率/FOV 时触发点能自动平移。听起来更严谨，**但它逼实现去反推债-85 那个 7.6e5 背后的
放大系数**——而 §3 批 1a 自己写着「触发点常数不许重新推导」。反推出来的系数就是第二份会漂的副本，
而且实测对不上（按 625→4.1e-4 反推 K≈6.7，按 7.6e5↔0.5px 反推 K≈11，两者差 1.6 倍，
因为债-85 用的是 `2^(floor(log2|x|)-23)` 的**台阶**函数而非连续相对精度）。
⟹ 正解：headroom 只输出**距离余量**（数量级），像素换算留给真去实测的那天；换焦距/分辨率时
**重新实测触发点并改那个具名常量**，不做公式换算。本节失效条件的判据 = 距离余量塌到 < 1 个数量级。
