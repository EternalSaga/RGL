# 外部 sample 资产实测（Epic / ORCA 四场景）

> **状态**：`现行`（2026-10-15 立，**活文档**：每转一批新资产补一节，被实测推翻的旧结论就地删）。
> 本篇 = **把 UE4 sample 场景喂进本渲染器之后，资产侧与导入侧的事实基线**：转换管线怎么跑、
> 每份资产的实测数字、材质/光照能力缺口的清单、机位与亮度标定读数。
> 🔴 **引擎侧未解决项不在本篇开副本** → `docs/还债总账.md`（本篇只给指针 + 资产侧读数）。
> 触发：用户把三个新 zip（SunTemple / EmeraldSquare / MEASURE_ONE）+ Bistro 第二场景转成 glb 目检。

## 1. 转换管线（唯一入口 = `tools/bistro_pack.py`，不另起一套）

两步，四份资产全部零改动复用 Bistro 那条既有管线：

```bash
assimp export X.fbx /tmp/.../out.gltf -f gltf2          # ① FBX → glTF2（+ out.bin）
python3 tools/bistro_pack.py out.gltf <TEXDIR> out.glb  # ② DDS→PNG 转码 + 材质回填 + 切线烘焙
```

- **为什么能零改动**：这批 sample 与 `Bistro_v5_2` 同约定——FBX + `*_BaseColor/_Normal/_Specular`
  的 BCn DDS，且 **Specular = R:AO / G:roughness / B:metalness**（README 逐字一致）。
- **本次修的工具两处**（`tools/bistro_pack.py`，已随本批改）：① 贴图名**大小写兜底**——ZeroDay 的
  FBX 引用 `tex\floor_BaseColor.dds` 而磁盘是 `FLOOR_BaseColor.dds`（738 张里只有 2 张不一致），
  旧代码直接 `KeyError: 46`；② **转码失败就地退出并点名**（旧行为是继续跑，产出一份少图的 glb，
  到目检阶段才发现，归因成本极高）。
- **别污染仓库配置副本**：一次性目检走 `just shot`（配置铺到 `build/rgl/.smoke/` 经 `RGL_CONFIG_DIR`
  注入），**不要改 `configs/`**——本次用的是同源的注入脚本，等价。
- 原件与解包工作目录不入库：`.gitignore` 已加 `/*.zip` 与 `/assets_raw/`。

## 3. 撞到的两堵容量墙（**都已有账**，本篇只补资产侧读数）

| 墙 | 失败形态 | 资产侧读数 | 账 |
|---|---|---|---|
| 单资产 task 数越 `maxMeshWorkGroupCount[0]` | 🔴 **静默 UB**（不 throw，每帧 VVL error） | EmeraldSquare 草地合并后 1,615,992 tris → `groupCountX=323,199` vs 上限 **65,535** | **债-126** |
| `kSceneMatrixCapacity = 4096` 实例墙 | 启动期 throw（响亮） | ZeroDay 7293 primitive → `scene instances (7293) exceed object matrix capacity (4096)`，**无降级路径** | `docs/还债总账.md` §3「规模上限清单」①（**已裁决不处理**，本资产是第一次被真实资产撞上） |

⚠ **两堵墙方向相反**：按材质合并 primitive 能把 ZeroDay 的实例数从 7293 压到 ~151（引擎侧实测本
模型只建出 151 个材质资产；glb 内是 166 个材质，**差额未查**），**但合并正是推高单资产三角形数、
撞债-126 的原因** ⟹ 两条必须同一批裁决，别单独"顺手合并一下"。

⚠ **doubleSided 资产的预算只有源三角形的一半**：草地 `Grass_blades.DoubleSided` 正反各存一份，
`ceil(2×1,615,992/10) = 323,199` 与 VVL 报的 `groupCountX` 逐位吻合（完整算术在债-126）。

## 4. 导入侧丢信息（assimp 这条路的三处，**都不是引擎缺口**）

1. **灯全丢，而且丢两层。** ① assimp 的 glTF 导出器不写 `KHR_lights_punctual`（`extensions: []`）；
   ② 🔴 更硬的一层：assimp 的 **FBX importer 把灯的位置也丢了**——`assimp export -f assjson` 里
   4 盏 `pointLight1..4` 的 `position` 全是 `[0,0,0]`，而名字含 `light` 的 15 个节点全是**灯具几何**
   （`Paris_Ceiling_Light_01` / `Wall_Light_Interior_01`…），transform 是单位阵。捞出来只有
   `diffuse=(280.8, 226.6, 124.1)`（钨丝暖光，归一化 `(1.0, 0.81, 0.44)`）+ quadratic attenuation=2，
   **没有位置** ⟹ 喂不进 `scene.lua` 的 `lights` 段。要位置得自己解 binary FBX 的 Light 节点。
2. **各场景灯数差别很大，别按"室内一定有一堆灯"规划。** 实测 `assimp info` 的 `Lights:` 行：
   `BistroInterior.fbx` **4**、`BistroExterior.fbx` **1**、`BistroInterior_Wine.fbx` **0**。
   官方 Wine 版本来就不靠 analytic lights 出参考图，靠 `emissiveFactor *= 1000` + 折射材质。
3. **自发光强度按官方配方差 1000 倍。** 官方 `.pyscene` 逐材质 `emissiveFactor *= 1000`，
   `bistro_pack.py` 写死 `EMISSIVE_STRENGTH = 1.0`。且本引擎**自发光不做 GI** ⟹ 火盆/霓虹只亮不照明。

🔴 **点光源不是引擎缺口**（写这条是为了防止下一个会话去"实现点光"）：`light.frag.slang` 的
`gl.params.y` 分支已实现点光（`toLight = position - P`，线性衰减 `saturate(1 - dist/range)`），
`Light.type = 1` + `scene.lua` 的 `lights` 列表段（`position/color/intensity/range/type`）就能喂，
上限 `kMaxLights = 8` ⟹ 上面那 4 盏**装得下**，缺的只是位置数据。

## 5. 材质能力缺口（需求直接从 `.pyscene` 数出来）

BistroInterior_Wine 的 `.pyscene` 点名的能力，逐条对现状：

| 能力 | 涉及材质 | 现状 |
|---|---|---|
| `specularTransmission=1` + IOR 1.33/1.55 | Glass / GlassWine / Water / Ice / white_wine / red_wine / beer（= 那 7 个 `alphaMode=BLEND` 材质） | ❌ 只有 alpha blend → **奶白块** |
| `volumeAbsorption` | white_wine / red_wine / beer / bottle_wine | ❌ 无体积 |
| `nestedPriority` 1/4/5/10 | 上面全部 + CookieJar / ToffeeJar | ❌ 要的是**排序/多趟**，不是 shader |
| `doubleSided` on glass | 全部玻璃 | ✅ 打包已回填 |
| `emissiveFactor *= 1000` | 5 个自发光材质 | ⚠ 有 emissive，强度写 1.0 且不做 GI（→ §4.3） |

**结论：这三行不是三件事**——透射/折射是一条通路，体积吸收与嵌套介质是它的两个加档。
基建也不是零：`ssr_trace` + `ssr_apply` 已在渲染图里（默认 `enabled=false` 时结构性旁路，不领 RT、
不建管线条目），折射要的"屏幕空间 trace + 粗糙度感知 apply + 装饰器加 pass 加 RT"这个形态项目已有
一份能跑的实现，改的是 miss 分支与偏移方向（反射 → 折射）。

## 6. 室内亮度标定（**"不黑"这件事本身是假的**）

- **读数**：Bistro 室内在**现交付档**（`san_giuseppe_bridge_4k.hdr`，env=1.0）下直接可读，
  吧台木饰面 / 地砖花纹 / 红壁纸 / 挂画 / 吊扇全部正确。SunTemple 室内：env=1 帧均值 **0.092**、
  env=5 帧均值 **0.266**，**零饱和**。
- 🔴 **但它靠的是"光穿墙"**：SH 天空辐照**不做遮挡**，封闭房间吃的是整颗户外天空。也就是说室内
  "不黑"是近似的产物，不是照明做对了——无窗那一侧本该更暗、更偏灯色。官方配方是
  `emissive ×1000` + 一堆 analytic lights，我们两条都没有。
- **env 强度必须按资产标定**：SunTemple 自带 `SunTemple_Skybox.hdr` 平均亮度 **0.023**，
  现用的 `san_giuseppe_bridge_4k.hdr` 是 **0.316**（差 **13.7×**）⟹ 同一档 env 强度换资产就废，
  SunTemple 要 5~10 才可读。
- **金属度分布要单独看**：SunTemple 48 材质里 **22 个 metalness > 0.5**（盾牌/雕像 = 1.0）
  ⟹ 无 SSR 时镜面反射无源可采 → 发黑（SSR 默认关）。
- ⚠ **无害但会被误当 bug 的一条**：这批资产的 `_Specular.dds` 的 **AO 通道恒为 0**，
  但引擎**根本不消费** `occlusionTexture` ⟹ 不影响画面，别去"修贴图"。

## 7. 顺带撞出来的引擎侧问题（与资产无关，但只有换资产/换档才撞得到）

- 🔴 **`--variant forward` 在 HEAD 上起不来**（→ **债-128**）。逐字消息：
  `off-graph contract: 'izb_mask' 的锚点 beforePass(kind=drawLight, state="light") 在编译图里命中 0 个
  pass（共 9 个 pass…）`。默认 bistro 配置同样红 ⟹ **与资产无关**；`--set shadow:izb.on=false`
  **不是绕行**（申报集是编译期定死的静态表，不看变体也不看门位）。代价 = forward/deferred 对拍做不了。
- 大资产的**目检结论要带条件**：EmeraldSquare 那批截图**不能算验收**——草地 task 数越限（债-126），
  RADV 对越限 `groupCountX` 到底是夹取还是丢整条 draw，**未取证**。
